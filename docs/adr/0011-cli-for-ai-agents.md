# ADR 0011: AI のエージェントが履歴を引くための CLI

ステータス: 採択

## 文脈

[ADR 0001](0001-import-claude-chat-logs-into-sqlite.md)〜[ADR 0010](0010-scan-downloads-for-claude-ai-exports.md) で、Claude Code、Cowork、claude.ai の会話を SQLite に取り込み、GUI（[ADR 0003](0003-tauri-log-viewer-with-search.md)）で閲覧・検索できるようにした。
利用者から、実装の作業中に AI（Claude Code などのエージェント）にこの履歴を引かせ、過去の経緯や決定を思い出させて文脈を戻したい、と求められた。

AI のエージェントは、シェルのコマンドを実行して標準出力を読むことができる。
いまある手段は、AI にとって次の点で使いにくい。

- GUI は人が操作するもので、エージェントからは使えない。
- `sqlite3` でデータベースを直接引くと、スキーマと JSON の形を AI が知っている必要がある。`raw` の JSON は大きく、そのまま出すと文脈の窓を食いつぶす。
- 取り込みの CLI（`claude-log-sources` など）は書きこみ用で、読むためのものが無い。

エージェントの文脈の窓は限られ、出力のトークンが多いほど費用もかかる。
AI に使わせる道具は、出力が短く形が決まっていて、ヘルプだけで使い方が分かり、概要から本文へ段階的に絞りこめることが要る。
adr-guard（このリポジトリが使う道具）も、AI がヘルプだけで使い方を把握できるよう、ヘルプに規則と出力の形と例を載せている。

検索の規則（3文字以上の語は trigram の索引、3文字未満は `LIKE`）と、写しの除去（[ADR 0005](0005-log-viewer-corrections-and-details.md)）は、GUI の Rust の実装にある。
この CLI は Bun と TypeScript で書くため、同じ規則を TypeScript でも持つことになる。

## 実装すること

### コマンド

読み取り専用のコマンド `chat-log` を足す。サブコマンドで役割を分ける。

| サブコマンド | 役割 |
|---|---|
| `chat-log context` | 文脈を戻すための最初の一手。指定したプロジェクト（既定は実行したディレクトリ）の最近のセッションと、それぞれの最後のやりとりを短く出す |
| `chat-log sessions` | セッションの一覧 |
| `chat-log search <語...>` | 本文の全文検索。一致したメッセージの抜粋を出す |
| `chat-log show <セッションID>` | 1つのセッションのメッセージを順に出す。範囲を絞れる |

- データベースは読み取り専用で開く。場所の決め方は [ADR 0001](0001-import-claude-chat-logs-into-sqlite.md)、[ADR 0004](0004-load-environment-from-dotenv.md)、[ADR 0007](0007-settings-and-setup-screen.md) と同じ（環境変数、`.env`、設定ファイル、既定）。
- スキーマの版が3より古いときは、取り込みを実行するよう標準エラー出力に書いて、終了コード2で終わる。
- `bin/install`（[ADR 0008](0008-install-compiled-commands.md)）は `chat-log` も実行ファイルにして入れる。
- `package.json` の `bin` に登録する。

### 共通のオプション

| オプション | 意味 | 既定 |
|---|---|---|
| `--provider <名前>` | 提供元で絞る（`claude-code`、`claude-cowork`、`claude-ai`） | すべて |
| `--cwd <ディレクトリ>` | セッションの `cwd` が、そのディレクトリか、その下のものに絞る。相対パスは絶対パスにする | `context` は実行したディレクトリ、ほかは絞らない |
| `--all` | `context` で `cwd` の絞りこみをしない | |
| `--since <時刻>` | その時刻より後のもの。ISO 8601 の日付・時刻か、`7d`、`12h`、`30m` の形の相対の時間 | なし |
| `--limit <数>`、`--offset <数>` | 件数と読み飛ばし | サブコマンドごと |
| `--json` | 1行に1つの JSON（JSON Lines）で出す | テキスト |
| `--max-chars <数>` | 1つのメッセージの本文を、この文字数で切る。`0` で切らない | サブコマンドごと |

- セッションID は、ほかのセッションと区別できれば、先頭の8文字以上で指定できる（git の短いハッシュと同じ考え方）。区別できなければ候補を標準エラー出力に書いて終了コード1で終わる。

### 出力（テキスト）

テキストの出力は、AI が読みやすく、トークンが少ない形にする。罫線や色は使わない。

`sessions`：1セッション1行、タブ区切り。

```
<最後の時刻>	<提供元>	<セッションIDの先頭8文字>	<メッセージ数>	<タイトル>	<cwd>
```

`search`：1件ごとに次の2行。抜粋の一致した部分は `**` で囲む。

```
<時刻>	<提供元>	<セッションIDの先頭8文字>#<メッセージの番号>	<役割>	<タイトル>
	<抜粋>
```

`show`：メッセージごとに見出しの行と本文。メッセージの番号は、そのセッションの中の通し番号（1始まり、写しを除いた順）。

```
## #<番号> <役割> <時刻>
<本文>
```

- 本文は、テキストのブロックだけを出す。`thinking` のブロックは既定では出さない（`--thinking` で出す）。
- `tool_use` は `[tool_use <名前>] <入力の JSON を1行にして先頭200文字>`、`tool_result` は `[tool_result] <本文の先頭200文字>` の1行にする（`--tools` で全文を出す。全文も `--max-chars` に従う）。その他のブロック（`injected_prompt_block`、画像など）は `[<種類>]` の1行にする。
- `--max-chars` で切ったときは、末尾に `…（N 文字のうち M 文字）` を付ける。
- 既定の `--limit` は 50、`--max-chars` は 2000。続きがあるときは、最後に `（続き：--offset <数>）` の行を出す。
- `--around <番号>` で、その番号の前後 `--limit` の半分ずつを出す。`search` の結果の `#<番号>` をそのまま渡せる。

`context`：

```
# <cwd か「すべて」> の最近のセッション（<件数>）

## <タイトル>（<提供元>、<セッションIDの先頭8文字>、<最初の時刻>〜<最後の時刻>、<メッセージ数> 件）
<最後のやりとり：最後の user と assistant のテキストを、それぞれ --max-chars で切ったもの>
```

- 既定は、最近の5セッション（`--limit`）、各セッションの最後の4件のテキストのメッセージ（`--messages`）、`--max-chars` は 500。
- 該当するセッションが無いときは、その旨を1行出し、`--all` を試すよう添える。

### 出力（`--json`）

1行に1つの JSON オブジェクトを出す。キーは snake_case。

- `sessions`：`provider`、`session_id`、`title`、`cwd`、`first_at`、`last_at`、`message_count`
- `search`：`provider`、`session_id`、`index`（メッセージの番号）、`uuid`、`timestamp`、`role`、`title`、`snippet`（強調は `**`）
- `show`：`index`、`uuid`、`timestamp`、`role`、`model`、`is_sidechain`、`blocks`（ブロックの配列。各ブロックは `kind` と、`text`、`name`、`input`、`truncated_from` など）
- `context`：セッションごとに1行。`sessions` のキーに `last_messages`（`show` の形の配列）を足す。

### 検索の規則

- GUI（[ADR 0003](0003-tauri-log-viewer-with-search.md)、[ADR 0005](0005-log-viewer-corrections-and-details.md)）と同じ。空白で区切った語のうち、3文字以上は二重引用符で囲んだ FTS5 の語として AND でつなぎ、3文字未満は `LIKE`（`%`、`_`、`\` をエスケープ）で絞る。写しは除く。新しい順。既定の `--limit` は 20。
- 抜粋は、FTS5 の `snippet()`（3文字以上の語があるとき）か、本文から切り出したもの。
- 既定の `--max-chars` は、抜粋には使わない（抜粋は短いため）。

### ヘルプ

`chat-log --help` と `chat-log <サブコマンド> --help` は、AI がヘルプだけで使えるように、次を載せる。

- 使う順序の勧め（`context` → `search` → `show --around`）。
- 各サブコマンドのオプション、既定の値、テキストと JSON の出力の形、終了コード。
- 例。
- データベースは毎時の取り込み（[ADR 0002](0002-periodic-sync-with-pm2.md)）で更新されるため、最新の1時間ぶんが無いことがある旨と、最新にしたいときは `bin/sync`（または `ai-chat-logs-sync`）を先に実行する旨。
- 履歴には秘密の情報が含まれうるため、出力を外へ送らない旨。

### 終了コード

| 終了コード | 意味 |
|---|---|
| 0 | 成功（結果が0件のときも含む） |
| 1 | 指定したセッションが無い、セッションID が区別できない |
| 2 | 使い方の誤り、データベースが無い・古い、設定の書式の誤り |

### 書き方

- クラスは使わない。
- 引数の解釈、時刻の解釈、検索の語の組み立て、抜粋の整形、ブロックの要約、テキストと JSON の整形は、入出力の無い関数にして、単体でテストする。

## 実装しないこと

- 書きこみ（取り込み、削除、編集）。
- MCP サーバー。CLI ならシェルを使えるどのエージェントからも使え、UNIX の道具と組み合わせられるため。必要になったら別の ADR で足す。
- 要約の生成（LLM で会話を要約すること）。出すのは記録された本文だけ。
- 意味での検索（埋めこみのベクトル）。
- 秘密の情報のマスキング。
- 実行中のセッション（いま書かれている記録）の除外。
- 検索の規則の Rust と TypeScript の共通化（下の「トレードオフ」）。

## テスト設計

`bun test` で、一時のデータベース（取り込みのコマンドで合成の履歴を取り込んだもの）を使って確かめる。

### 純粋な関数

1. 時刻の解釈：ISO 8601 の日付・時刻、`7d`・`12h`・`30m`、正しくない形はエラー。
2. 検索の語の組み立て：GUI と同じ規則（3文字以上は引用して AND、3文字未満は `LIKE` のパターン、`%`・`_`・`\` のエスケープ、FTS5 の構文の文字が語として扱われる）。
3. 抜粋の強調の区切り（U+E000、U+E001）を `**` に変える。
4. ブロックの要約：`tool_use`、`tool_result`、`thinking`（既定で出さない、`--thinking` で出す）、その他の種類。
5. `--max-chars` での切りつめと、末尾の注記。`0` で切らない。
6. セッションID の先頭の一致：一意なら決まる、複数なら候補、8文字未満はエラー。

### サブコマンド

7. `sessions`：新しい順、タブ区切りの形、`--provider`・`--cwd`（その下のディレクトリを含み、名前が前方だけ一致するディレクトリは含まない）・`--since`・`--limit`・`--offset`、`--json` のキー。
8. `search`：3文字以上と3文字未満の語、写しが1回だけ出る、`#<番号>` が `show` の番号と一致する、`--json` のキー。結果が0件で終了コード0。
9. `show`：順序と番号、`thinking` と `tool_use`・`tool_result` の扱いと `--thinking`・`--tools`、`--around`、続きの行、先頭8文字での指定、無いセッションで終了コード1、区別できないときに候補と終了コード1。
10. `context`：実行したディレクトリ（`cwd` を一時ディレクトリにして実行）のセッションだけが出る、`--all`、`--limit`・`--messages`、該当が無いときの1行、`--json`。
11. データベースが無いとき、スキーマが古いときに、終了コード2とメッセージ。
12. `--help` に、各サブコマンド、出力の形、終了コード、使う順序の勧めが含まれる。
13. 出力の量：既定のオプションで、長いメッセージ（10万文字）を含むセッションの `show` の出力が、`--limit` × `--max-chars` 程度に収まる。
14. `bin/install` が `chat-log` を入れ、実行ファイルでも同じ結果になる。

### 手で確かめること

1. このリポジトリで作業している Claude Code に `chat-log --help` を読ませ、ほかの説明なしに、`context`、`search`、`show` を使って過去の決定（例：「[ADR 0005](0005-log-viewer-corrections-and-details.md) で写しを除くことにした理由」）を探せるか。
2. 実際のデータベースで、`context` と `search` の応答が1秒程度で返るか。

## トレードオフ

- 検索の規則を、GUI の Rust と、この CLI の TypeScript の2か所に持つ。CLI から GUI のバイナリを呼ぶ、または SQL のビューに規則を移せば1か所にできるが、前者は GUI のビルドを要し、後者は FTS5 の語の引用を SQL で書く必要がある。テストで同じ規則を確かめて、ずれを防ぐ。
- 出力を切りつめるため、AI は全文を一度には読めない。そのかわり、文脈の窓と費用を守る。全文が要るときは `--max-chars 0` と `--tools` で出せる。
- 1つのコマンドにサブコマンドを持たせる。サブコマンドごとに別のコマンドにするほうが UNIX の流儀に近いが、AI が1つのヘルプから全体を把握できることを優先する。読み取り専用で、役割が同じ（履歴を引く）ため、まとめても絡み合いは小さい。
- 履歴には秘密の情報が含まれうる。AI の文脈に入れたものは、そのエージェントの提供元に送られる。マスキングはせず、ヘルプで注意を促すにとどめる。
