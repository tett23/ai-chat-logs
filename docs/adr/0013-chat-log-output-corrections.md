# ADR 0013: chat-log の出力の修正

ステータス: 採択

## 文脈

[ADR 0011](0011-cli-for-ai-agents.md) の `chat-log` を実装した後、この会話の文脈を持たない別のエージェントに、ヘルプだけを頼りに過去の決定を探させた（[ADR 0011](0011-cli-for-ai-agents.md) の「手で確かめること」の1）。
エージェントは正しい答えにたどり着いたが、次の問題を報告した。

1. `search` の抜粋の強調が、`****重複****` や `**実**行**` のように崩れる。
2. `search` は思考（thinking）にも当たるが、結果の行からは本文か思考かが分からない。勧めた手順（`search` → `show --around`）で開くと、思考は既定で出さないため、当たった内容が見えない。
3. `show` の既定で、思考だけのメッセージが、本文の無い見出し（`## #415 assistant ...`）として並び、ノイズになる。
4. `--tools` を付けなくても、`tool_result` の中の画像の base64 が200文字ぶん出る。
5. ヘルプが分かりにくい。`search` は既定で `cwd` に絞らないが `context` は絞ること、`--around` と `--limit 1` の組み合わせの結果、`--around` と組み合わせたときの「（続き：--offset N）」の行の意味が書かれていない。

1 を実際のデータで調べた。
2文字の語は索引を使わず、本文から抜粋を切り出す（[ADR 0011](0011-cli-for-ai-agents.md)、[ADR 0005](0005-log-viewer-corrections-and-details.md)）。
本文の約14%（索引の 21,677 件のうち 3,018 件）は、Markdown の太字の `**` を含む。
強調の記号に `**` を使ったため、本文の `**重複**` の中の「重複」を強調すると `****重複****` になり、本文の `**` と強調の `**` の区別がつかなくなっていた。
強調の記号の候補について、本文に現れる件数を数えた結果は、`⟦⟧` が1件、`[[ ]]` が59件、`>> <<` が31件、`⟪⟫`・`〘〙`・`⦃⦄` が0件だった。

4 は、`tool_result` の `content` の配列の中の、テキストでないブロック（画像など）を JSON のまま出していたためである。

[ADR 0011](0011-cli-for-ai-agents.md) はコミット済みのため、出力の形の変更をこの ADR に記録する。

## 実装すること

### 1. 強調の記号

- `search` の抜粋の強調を、`**` から `⟪`（U+27EA）と `⟫`（U+27EB）に変える。テキストと `--json` の `snippet` の両方。
- 強調する部分が重なったり隣りあったりするときは、1つにまとめる（`⟪⟪語⟫⟫` や `⟪語⟫⟪語⟫` にしない）。
- ヘルプの説明を合わせる。

### 2. 思考に当たったとき

- `search` の各結果について、一致した語が、メッセージのテキストのブロックにあるか、思考のブロックにあるかを調べる。
- テキストの出力では、思考のブロックにだけ一致したときは、抜粋の行の先頭に `[thinking] ` を付ける。
- `--json` では `matched_in` に、`["text"]`、`["thinking"]`、`["text", "thinking"]` のいずれかを入れる。
- `show --around <番号>` では、中心のメッセージ（その番号のもの）の思考は、`--thinking` が無くても出す。
- ヘルプの使う順序の勧めに、`[thinking]` の付いた結果も `show --around` で読めることを書く。

### 3. 思考だけのメッセージ

- `show` のテキストの出力では、表示する本文が無いメッセージ（思考だけで `--thinking` が無いもの）を出さない。見出しも出さない。番号は詰めない（番号の飛びで省いたことが分かる）。
- `--json` では、これまでどおりすべてのメッセージを出す。
- `--limit` は、省いたメッセージも数える（番号の範囲で数える）。
- `context` の最後のメッセージは、これまでどおりテキストのあるメッセージだけから選ぶ。

### 4. base64

- `tool_result` の `content` の配列の中で、テキストでないブロックは `[<種類>]`（例：`[image]`）にする。
- テキストの中の、連続した200文字以上の base64 の文字（`A-Z`、`a-z`、`0-9`、`+`、`/`、`=`）は、`[base64 <文字数> 文字]` に置きかえる。`data:<型>;base64,` が前にあれば、それも含めて置きかえる。
- 置きかえは、`show` のテキストと `--json` の `blocks`、`context` に効く。`--tools` を付けても置きかえる。
- 検索の索引（[ADR 0003](0003-tauri-log-viewer-with-search.md)）は変えない（ツールの入出力は索引に入っていない）。

### 5. ヘルプ

次を書き足す。

- `context` だけが既定で実行したディレクトリに絞ること。`sessions`、`search`、`show` は絞らず、プロジェクトに絞るには `--cwd .` を付けること。例にも `--cwd .` を使う。
- `--around <番号>` は、番号を含む `--limit` 件を出し、番号の前に `--limit` の半分（切り捨て）件を置くこと。`--limit 1` なら、その番号の1件だけになること。
- 続きの行の形を「（続き：#<次の番号> から。--offset <数> で出す）」に変え、`--around` と組み合わせたときもその番号から続けて出せることが分かるようにする。前があるとき（`--around` で1件目より後から始まったとき）は、先頭に「（前：#1〜#<数> は --offset 0 で出す）」の行を出す。

## 実装しないこと

- 同じ文面のメッセージ（繰り返されたプロンプト）をまとめること。写しの除去（[ADR 0005](0005-log-viewer-corrections-and-details.md)）は `uuid` で行い、文面では行わない。
- `search` の抜粋の強調の記号を利用者が選べること。
- 思考を検索の対象から外すこと。

## テスト設計

`bun test` で確かめる。

1. 強調：本文が `**重複**` を含むとき、抜粋が `**⟪重複⟫**` になる。重なる・隣りあう強調が1つにまとまる。FTS5 の `snippet()` の区切り（U+E000、U+E001）も `⟪⟫` になる。`--json` の `snippet` も同じ。
2. 思考：思考にだけ当たる結果の抜粋の行が `[thinking] ` で始まる。テキストに当たる結果には付かない。`--json` の `matched_in` が正しい。`show --around` の中心のメッセージの思考が、`--thinking` なしで出る。中心以外の思考は出ない。
3. 思考だけのメッセージ：`show` のテキストの出力に、そのメッセージの見出しが出ない。番号は詰まらない。`--json` には出る。`--limit` が番号の範囲で数える。
4. base64：`tool_result` の配列の中の画像のブロックが `[image]` になる。テキストの中の200文字以上の base64 と `data:image/png;base64,...` が `[base64 N 文字]` になる。199文字以下は置きかえない。`--tools` でも置きかえる。`--json` の `blocks` でも置きかえる。
5. ヘルプ：`--cwd .`、`--around` と `--limit` の関係、続きと前の行の説明が含まれる。続きの行が「（続き：#<次の番号> から。--offset <数> で出す）」、前の行が「（前：#1〜#<数> は --offset 0 で出す）」の形で出る。

### 手で確かめること

[ADR 0011](0011-cli-for-ai-agents.md) の手で確かめることの1を、同じ問いでやりなおし、上の5つの問題が出ないことを確かめる。

## トレードオフ

- `⟪⟫` は、いまの本文には現れないが、将来の本文に現れる可能性はある。その場合は区別できなくなるが、本文に `**` が現れる頻度（約14%）よりはるかに小さい。
- 一致した場所が本文か思考かを、出力のたびに `raw` を解析して調べる。検索の結果の件数（既定で20）だけなので、負荷は小さい。
- 思考だけのメッセージを `show` のテキストで省くため、AI は番号の飛びの理由を推測する必要がある。ヘルプに書いて扱う。`--json` には残すので、情報は失われない。
- base64 を置きかえるため、`--tools` でも画像の中身は読めない。AI が base64 の画像を文字として読む意味は無い。
