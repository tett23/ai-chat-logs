# ADR 0014: GUI の会話を少しずつ読みこむ

ステータス: 採択

## 文脈

GUI（[ADR 0003](0003-tauri-log-viewer-with-search.md)）は、セッションを開くと、`get_session` でそのセッションのメッセージをすべて受け取り、すべてを DOM に組み立てる。
[ADR 0005](0005-log-viewer-corrections-and-details.md) で、折りたたんだ部分を開いたときに組み立てることと、長いブロックを 4,000 文字で切ることで負荷を減らしたが、メッセージの数に比例する負荷は残っている。

2026-10-22 時点で、最大のセッションは 79,083 件のメッセージを持つ（2026-10-15 に確かめたときは 26,834 件で、開くのに約10秒かかった）。
セッションは使うほど長くなるため、すべてを読みこむ方式では、開くのにかかる時間と使うメモリが増え続ける。
利用者から、長い会話の読みこみと描画の負荷を、無限スクロールで減らすよう求められた。

検索の結果からセッションを開くと、一致したメッセージまでスクロールする（[ADR 0003](0003-tauri-log-viewer-with-search.md)）。
少しずつ読みこむ場合、一致したメッセージが最初に読みこむ範囲に入っている必要がある。

[ADR 0011](0011-cli-for-ai-agents.md) の `chat-log` は、写しを除いたメッセージに1始まりの通し番号を付け、番号の範囲でメッセージを引く。
GUI でも同じ番号を使えば、範囲で引くことも、検索の結果の位置を示すこともできる。

## 実装すること

### バックエンド

- 新しいコマンド `get_messages`（引数は `session_id`、`from`、`limit`）。そのセッションの写しを除いたメッセージ（`session_messages`、[ADR 0005](0005-log-viewer-corrections-and-details.md)）に、ファイルのパス、`generation`、行番号の順で1始まりの番号を付け、番号が `from` から `from + limit - 1` のものを返す。あわせて、そのセッションのメッセージの総数を返す。
- 各メッセージに番号（`index`）を付ける。ほかの項目（`rowid`、`uuid`、時刻、役割、モデル、サイドチェーンか、ブロック）と、ブロックの切りつめ（[ADR 0005](0005-log-viewer-corrections-and-details.md)）は `get_session` と同じ。
- `search` の結果の各件に、そのメッセージの番号（`index`）を付ける。
- `get_session` は消す。

### フロントエンド

- 1回に読みこむのは100件（以下「1ページ」）。
- 一覧からセッションを開いたときは、番号1から1ページを読みこむ。
- 検索の結果から開いたときは、一致したメッセージの番号を N として、N − 50（1より小さければ1）から1ページを読みこみ、N のメッセージまでスクロールして強調する（[ADR 0003](0003-tauri-log-viewer-with-search.md) と同じ）。
- 会話の欄を下端の近く（残り 600px 以内）までスクロールしたら、続きの1ページを読みこんで末尾に足す。最後のメッセージまで読みこんだら、それ以上読まない。
- 1件目より後から読みこんでいるときは、上端の近く（600px 以内）までスクロールしたら、前の1ページを読みこんで先頭に足す。足した後も、見ていたメッセージの位置が画面の上で動かないように、スクロールの位置を足した分の高さだけずらす。
- 読みこんでいる間は、同じ向きの読みこみを重ねない。別のセッションを開いたら、前のセッションの読みこみの結果は捨てる。
- 会話の欄の先頭か末尾に、読みこみ中であることと、`<読みこんだ範囲の最初の番号>〜<最後の番号> / <総数>` を小さく出す。
- 読みこむ範囲の計算（最初の範囲、続き、前）は、入出力の無い関数にする。

### しないこと（描画の範囲）

読みこんだメッセージは、画面の外に出ても DOM から消さない（仮想スクロールにはしない）。
1回のスクロールで読みこむのは1ページだけなので、利用者がスクロールした分だけ増える。

## 実装しないこと

- 仮想スクロール（画面の外のメッセージを DOM から外すこと）。必要になったら別の ADR で足す。
- メッセージの番号を指定して移動する入力欄。
- 会話の中の検索（ブラウザの検索で足りる範囲だけを読む）。
- `chat-log`（[ADR 0011](0011-cli-for-ai-agents.md)）と GUI での、番号の付け方の SQL の共通化。両方とも `session_messages` に同じ順序で番号を付ける。

## テスト設計

### バックエンド（`cargo test`）

1. `get_messages`：番号が1始まりで、ファイルのパス、`generation`、行番号の順に付く。`from` と `limit` の範囲だけが返る。総数が正しい。範囲が総数を超えても、ある分だけが返る。
2. 写しのあるセッションで、写しが番号に入らない（番号が飛ばない）。
3. `search` の結果の `index` が、`get_messages` の番号と一致する。
4. ブロックの切りつめが `get_session` のときと同じに効く。

### フロントエンド（`bun test`）

5. 最初の範囲：一覧から開いたときは 1〜100。検索の結果から開いたときは N − 50 から100件（N が 50 以下なら1から）。総数が100より少なければ総数まで。
6. 続きの範囲：読みこんだ最後の番号の次から100件。最後まで読みこんでいれば無し。
7. 前の範囲：読みこんだ最初の番号の前の100件（1より前は切る）。最初が1なら無し。

### 手で確かめること

1. 最大のセッション（7万件以上）を一覧から開くと、1秒程度で最初のメッセージが出る。下へスクロールすると続きが足される。
2. 検索の結果から長いセッションの途中のメッセージを開くと、そのメッセージまでスクロールして強調される。上へスクロールすると前のメッセージが足され、見ていた位置が動かない。
3. 読みこみ中に別のセッションを開いても、前のセッションのメッセージが混ざらない。

## トレードオフ

- 仮想スクロールにしないため、長いセッションを末尾までスクロールすると、DOM は全件ぶんになる。そのかわり、実装が単純で、ブラウザの検索やテキストの選択が素直に動く。最初の表示は、セッションの長さによらず速くなる。
- 前の範囲を読みこむときにスクロールの位置をずらすため、読みこむ瞬間に表示がちらつくことがある。
- 番号の付け方を、`chat-log` の TypeScript と GUI の Rust の2か所に持つ。どちらも `session_messages` に同じ `ORDER BY` を付けるだけなので、ずれる余地は小さい。
