# ADR 0016: GUI の会話を新しい順に出し、番号を時刻の順に付ける

ステータス: 採択（未実装）

## 文脈

GUI（[ADR 0003](0003-tauri-log-viewer-with-search.md)）は、会話のメッセージを古い順（上が最初、下が最後）に出す。
[ADR 0014](0014-load-conversations-in-pages.md) で、会話を100件ずつ読みこむようにした。一覧から開くと最初の100件を読みこみ、下へスクロールすると続きを読みこむ。

長いセッション（7万件以上）では、知りたいのはたいてい最近のやりとりである。
古い順のままでは、最近のメッセージに着くまで、最初から何百ページも読みこみながらスクロールする必要がある。
利用者から、会話を降順（新しい順）で出すよう求められた。

新しい順に並べる実装を試したところ、最大のセッション（Golem）の最後のページが、サブエージェントの記録ばかりになった。
メッセージの番号は、ファイルのパス、`generation`、行番号の順に付けている（[ADR 0005](0005-log-viewer-corrections-and-details.md)、[ADR 0014](0014-load-conversations-in-pages.md)、[ADR 0011](0011-cli-for-ai-agents.md)）。
サブエージェントの記録は、親のセッションのファイル（`<セッションID>.jsonl`）より後ろのパス（`<セッションID>/subagents/…`）にあるため、番号の大きいほうにまとまる。
番号の順は、時間の順になっていない。

[ADR 0003](0003-tauri-log-viewer-with-search.md)、[ADR 0005](0005-log-viewer-corrections-and-details.md)、[ADR 0011](0011-cli-for-ai-agents.md)、[ADR 0014](0014-load-conversations-in-pages.md) はコミット済みのため、番号の付け方、並び順、読みこむ範囲の変更をこの ADR に記録する。

## 実装すること

### 番号の付け方（[ADR 0005](0005-log-viewer-corrections-and-details.md)、[ADR 0011](0011-cli-for-ai-agents.md)、[ADR 0014](0014-load-conversations-in-pages.md) を改める）

- セッションのメッセージ（写しを除く `session_messages`）の番号を、時刻（`timestamp`）の順に付ける。時刻が同じものは、これまでどおりファイルのパス、`generation`、行番号の順にする。
- GUI の `get_messages` と検索の結果の番号、`chat-log` の `show`・`search`・`context` の番号の両方に効く。GUI と `chat-log` の番号は同じになる。
- 写しの除去（どの写しを残すか）の順は変えない（パス、`generation`、行番号の順で最初のもの）。

### 並び順

- 会話の欄では、メッセージを新しい順に出す。いちばん上が最後のメッセージ（番号が最大、時刻が最も新しい）、下へ行くほど古い。
- 1つのメッセージの中のブロックの順（テキスト、思考、ツールなど）は変えない。
- 番号は古い順（時刻の順）に1から付く。

### 読みこむ範囲（[ADR 0014](0014-load-conversations-in-pages.md) を改める）

- 一覧から開いたときは、最後の1ページ（番号が `総数 − 99` から総数まで。総数が100未満なら1から）を読みこみ、いちばん上（最後のメッセージ）を出す。総数は、一覧の項目が持つメッセージ数（`session_summaries.message_count`）を使う。読みこんだ結果の総数が一覧の数と違えば（取り込みで増えたとき）、その総数で最後の1ページを読みこみなおす。
- 検索の結果から開いたときは、これまでどおり一致したメッセージの番号 N の 50 件前から1ページを読みこみ、N のメッセージまでスクロールして強調する。
- 下端の近くまでスクロールしたら、より古い1ページを読みこんで下に足す。
- 上端の近くまでスクロールしたら、より新しい1ページを読みこんで上に足し、見ていた位置が動かないようにスクロールの位置をずらす。
- いちばん古いメッセージ（番号1）まで読みこんだら下には足さない。いちばん新しいメッセージ（総数）まで読みこんだら上には足さない。
- 表示が画面より短いあいだは、より古いページを続けて読みこむ。
- 範囲の表示（`<最初の番号>〜<最後の番号> / <総数>`）は変えない。

## 実装しないこと

- 古い順と新しい順の切り替え。
- `chat-log` の並び順の変更（`show` は番号の順、つまり古い順のまま。番号の付け方だけが時刻の順に変わる）。
- セッションの一覧と検索の結果の並び順の変更（どちらも、すでに新しい順）。

## テスト設計

### 番号の付け方

1. GUI（`cargo test`）：親のセッションとサブエージェントの記録の時刻が入りまじるとき、`get_messages` の番号が時刻の順に付く。時刻が同じものは、パスと行番号の順。検索の結果の番号も同じ。
2. `chat-log`（`bun test`）：同じ形の履歴で、`show` の番号と順序が時刻の順になり、`search` の `#<番号>` と一致する。

### フロントエンド（`bun test`）

3. 最初の範囲：一覧から開いたときは、総数が 79,083 なら 78,984〜79,083、総数が7なら 1〜7、総数が0なら無し。検索の結果から開いたときは、[ADR 0014](0014-load-conversations-in-pages.md) と同じ。
4. より古い範囲：読みこんだ最初の番号の前の100件（1より前は切る）。最初が1なら無し。
5. より新しい範囲：読みこんだ最後の番号の次から100件（総数で切る）。最後が総数なら無し。
6. メッセージを新しい順に並べる関数：番号の大きい順になる。

### 手で確かめること

1. 長いセッションを一覧から開くと、いちばん上に最後のメッセージ（時刻が最も新しいもの）が出る。サブエージェントの記録がまとまって先頭に来ない。範囲の表示が `<総数 − 99>〜<総数> / <総数>` になる。下へスクロールすると古いメッセージが下に足される。
2. 検索の結果から途中のメッセージを開くと、そのメッセージまでスクロールして強調される。上へスクロールすると新しいメッセージが上に足され、見ていた位置が動かない。下へスクロールすると古いメッセージが下に足される。
3. 短いセッション（100件未満）を開くと、全部が新しい順に出る。

## トレードオフ

- 会話を上から下へ時系列に読みたいときは、下から上へ読むことになる。最近のやりとりにすぐ着けることを優先する。
- 1つのメッセージの中は上から下へ読むので、メッセージの間の順と、メッセージの中の順が逆向きになる。
- 番号の付け方を変えるため、変える前に `chat-log` で得た番号は、変えた後には別のメッセージを指す。番号は保存して使うものではないので、影響は小さい。
- 時刻の順に番号を付けるにも、セッションの全件の並べかえが要る。いまもパスの順で全件を並べかえているので、負荷はほぼ変わらない。
- GUI と `chat-log` で並び順が異なる。`chat-log` は AI が順に読むための道具で、番号の範囲で引く使い方のため、古い順のままにする。
