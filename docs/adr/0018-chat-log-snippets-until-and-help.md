# ADR 0018: chat-log の抜粋、`--until`、`--around` の既定、ヘルプの用語

ステータス: 採択（未実装）

## 文脈

`chat-log`（[ADR 0011](0011-cli-for-ai-agents.md)、[ADR 0013](0013-chat-log-output-corrections.md)）は、AI のエージェントが過去の会話から文脈を戻すための CLI である。
[ADR 0013](0013-chat-log-output-corrections.md) の実装の後、この会話の文脈を持たないエージェントに、ヘルプだけを頼りに「写しを1回だけ出すことにした理由」を探させた。
答えにはたどり着いたが、次の4点が使いにくいと報告された。

1. AND で検索しても、抜粋で強調（`⟪ ⟫`）されるのが片方の語だけのことがある。もう片方の語がどこで一致したのか、抜粋からは分からず、毎回 `show` が要る。
2. 新しい順に並ぶため、探している時期より後の（その調査そのものを話題にした）メッセージが上に来る。期間の終わりで絞る `--until` が無い。
3. ヘルプの「写しは1回だけ出る」の「写し」が何を指すのか、定義が無い。
4. `show --around` で `--limit` を付けないと、既定の 50 件が出て出力が長い。

手元で確かめた原因は次のとおり。

- 1 の原因は2つある。
  - 3文字未満の語だけの検索（`LIKE`）は、最初に一致した語の前後32文字だけを抜粋にする。ほかの語がその外にあれば強調されない。`chat-log search 写し 重複 --cwd .` の1件目は「写し」だけが強調された。
  - 3文字以上の語の検索は、FTS5 の `snippet()`（16トークンの窓）を使う。語が離れていると、窓に両方が入らない。`chat-log search adr-guard pre-commit` の1件目は「adr-guard」だけが強調された。
  - また、trigram の窓の端で語が途中で切れ、`⟪adr-g⟫`、`⟪adr-gua⟫` のように語の一部だけが強調されることがある。
- 2：`--since` は、検索ではメッセージの時刻、`sessions` と `context` では最後の時刻（`last_at`）がその時刻より後のものに絞る。終わりで絞る手段は無い。
- 3：「写し」はこのリポジトリの用語（[ADR 0005](0005-log-viewer-corrections-and-details.md)）で、ヘルプでは定義していない。
- 4：`--around` は `--limit` の件数を使い、`show` の既定の `--limit` は 50 である。

## 実装すること

### 1. 抜粋（`search`）

- 抜粋を、FTS5 の `snippet()` ではなく、本文（`record_texts.text`）から TypeScript で作る。3文字以上の語の検索と、3文字未満の語の検索で、同じ作り方にする。
- 語ごとに、最初に一致した位置の前後 32 文字を切り出す。一致は ASCII の大文字と小文字を区別しない（`LIKE` と同じ）。
- 切り出した範囲を本文の順に並べ、重なる・隣りあう範囲は1つにまとめる。範囲のあいだと、本文の先頭・末尾で切ったところに `…` を置く。
- どの範囲でも、すべての語の一致を `⟪ ⟫` で囲む（重なる・隣りあう強調は1つにまとめる。[ADR 0013](0013-chat-log-output-corrections.md) と同じ）。語は途中で切らない。
- 本文にどの語も見つからないとき（FTS5 と文字の比べ方が違って一致したときなど）は、本文の先頭の 64 文字を抜粋にする。
- `--json` の `snippet` も同じものにする。

### 2. `--until`

- 共通のオプションに `--until <時刻>` を足す。書き方は `--since` と同じ（`2026-10-01`、`2026-10-01T12:00:00+09:00`、`7d`、`12h`、`30m`）。
- `search`：メッセージの時刻がその時刻より前のもの。
- `sessions`、`context`：最初の時刻（`first_at`）がその時刻より前のセッション。`--since`（最後の時刻がその時刻より後）と合わせると、期間に重なるセッションになる。
- `show` には効かない（`--since` と同じ）。
- `--since` が `--until` 以後でもエラーにしない（結果は0件になる）。

### 3. ヘルプの用語と時刻

- 全体のヘルプに「用語」の節を足し、次を書く。
  - 写し：fork したセッションなどで、同じ提供元・セッションID・`uuid` のレコードが複数のファイルにあるもの。パス、`generation`、行番号の順で最初の1つだけを使い、ほかは会話・検索・件数から除く。
  - メッセージの番号：セッションの中の通し番号（1始まり、時刻の順。写しは数えない）。
- `search` のヘルプの「写しは1回だけ出る」に、用語の節を参照させる。
- 時刻の書き方に、日付だけのとき（`2026-10-01`）は UTC の 0 時、時刻にオフセットが無いとき（`2026-10-01T12:00:00`）は手元の時刻帯で解釈することを書く（いまの `--since` の解釈を書くだけで、変えない）。

### 4. `--around` の既定

- `show --around` で `--limit` を付けないときの件数を 10 にする（番号の前に 5 件）。
- `--around` が無いときの既定（50 件）は変えない。

### ドキュメント

- `docs/specifications.md` の `chat-log` の節と、README の `chat-log` の例を、上に合わせて直す。

## 実装しないこと

- GUI の抜粋の変更（GUI はヒットを開けば前後が読めるので、今回は `chat-log` だけにする）。
- 日付だけの時刻を手元の時刻帯で解釈するような、時刻の解釈の変更。
- `show` を期間で絞ること。
- 抜粋の長さを変えるオプション。

## テスト設計

### 抜粋（`bun test`、関数）

1. 2つの語が 64 文字より離れているとき、抜粋に両方の語が `⟪ ⟫` で入り、あいだに `…` が入る。
2. 2つの語が近いとき、範囲が1つにまとまり、`…` は先頭と末尾で切ったところにだけ入る。
3. 同じ語が範囲の中に複数あれば、すべて強調される。大文字と小文字が違っても強調される。
4. どの語も見つからないとき、本文の先頭の 64 文字（長ければ末尾に `…`）。

### `chat-log`（`bun test`、コマンド）

5. 3文字以上の語2つが離れた本文の `search`：両方の語が強調され、語の一部だけの強調（`⟪` の直後か `⟫` の直前で語が切れたもの）が無い。
6. 3文字未満の語2つが離れた本文の `search`：両方の語が強調される。
7. `--until`：`search` が、その時刻より前のメッセージだけを出す。`sessions` が、最初の時刻がその時刻より前のセッションだけを出す。`--since` と合わせると期間で絞れる。書き方の誤りは終了コード2。
8. `show --around N` を `--limit` なしで実行すると、番号 N−5〜N+4 の10件の範囲になる。`--limit` を付ければその件数。`--around` なしの既定は 50 件のまま。
9. ヘルプに、用語の節（写し、メッセージの番号）、`--until`、時刻の解釈が出る。

### 手で確かめること

1. 文脈を持たないエージェントに、ヘルプだけを頼りに [ADR 0013](0013-chat-log-output-corrections.md) の確認と同じ問い（写しを1回だけ出すことにした理由）を解かせ、4点が報告されないことを確かめる。

## トレードオフ

- 抜粋を TypeScript で作るため、ヒットごとに本文の全文を読む。1ページは既定で 20 件で、本文の読み出しは問い合わせの時間に比べて小さい。
- 語の数だけ範囲が増えるので、抜粋が長くなる（2語で最大約 130 文字）。どの語がどこで一致したかが分かることを優先する。
- `--until` の `sessions` と `context` は最初の時刻で比べるため、期間の前に始まって期間の中まで続いたセッションも入る。期間に重なるものを出すほうが、文脈を戻す用途に合う。
- `--around` の既定が 10 件になるので、前後をもっと読みたいときは `--limit` を付けるか、出力の最後の「続き」の行に従う。
