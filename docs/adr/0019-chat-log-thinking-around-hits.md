# ADR 0019: chat-log の show --around で前後の思考も出す

ステータス: 採択

## 文脈

`chat-log show --around <番号>`（[ADR 0011](0011-cli-for-ai-agents.md)）は、`search` の結果の前後を読むための出し方である。
[ADR 0013](0013-chat-log-output-corrections.md) で、中心のメッセージ（その番号のもの）の思考は `--thinking` が無くても出すようにした。中心以外の思考は出さない。
また、表示するものが無いメッセージ（思考だけで `--thinking` が無いものなど）は、見出しも出さない。

[ADR 0018](0018-chat-log-snippets-until-and-help.md) の実装の後、文脈を持たないエージェントに、ヘルプだけを頼りに「写しを1回だけ出すことにした理由」を探させた。
`show f0f40b1f --around 420` では、#417〜#422 の5件しか出なかった。決定が書かれた #424 は思考だけのメッセージだったため、省かれて見えなかった。
エージェントは `--thinking` を付けて読みなおす必要があった。ヘルプにある「その番号のメッセージは思考を出す」が前後には及ばないことに、気づきにくいとも報告された。
同じ報告で、`search` の結果の多くが思考への一致（`[thinking]`）だったことも挙げられた。
決定の経緯は、思考に書かれていることが多い。

取り込んだ履歴（2026-10-22 時点）で、次のことを確かめた。

- assistant のメッセージのうち、内容が配列の 86,587 件の 34%（29,715 件）は、思考のブロックだけからなる。
- 思考のブロック 30,698 個のうち、87.5%（26,865 個）は本文が空である（Claude Code が本文を残さず、署名だけを残したもの）。本文のあるものは 3,833 個（500 文字以下が 3,646 個、それより長いものが 187 個）。
- いまの `--thinking` は、本文が空の思考も `[thinking] ` だけの行として出す。思考だけのメッセージの多くは、`--thinking` を付けると、中身の無い行を出す。

## 実装すること

### 1. `--around` では窓の中のすべての思考を出す

- `show --around <番号>` のテキストの出力では、読みこんだ範囲（`--limit` 件。既定 10 件、[ADR 0018](0018-chat-log-snippets-until-and-help.md)）のすべてのメッセージの思考を、`--thinking` が無くても出す。[ADR 0013](0013-chat-log-output-corrections.md) の「中心のメッセージだけ」を改める。
- 思考は `--max-chars` で切る（本文と同じ）。
- `--around` が無いときは、これまでどおり `--thinking` があるときだけ思考を出す。

### 2. 本文が空の思考は出さない

- テキストの出力では、本文が空（空白だけを含む）の思考のブロックは、`--thinking` や `--around` があっても出さない。
- そのため、本文が空の思考だけからなるメッセージは、表示するものが無いメッセージとして省く（番号は詰めない。[ADR 0013](0013-chat-log-output-corrections.md) と同じ）。
- `--json` は変えない（空の思考も `{"kind": "thinking", "text": ""}` として出す）。

### 3. ヘルプ

- `show` のヘルプの `--around` の説明を「その範囲のメッセージの思考も、`--thinking` が無くても出す」に改める。
- 本文が空の思考（署名だけが残ったもの）は出さないことを書く。
- `search` のヘルプの「show --around はその番号のメッセージの思考も出す」を、範囲のメッセージに改める。

### ドキュメント

- `docs/specifications.md` の `chat-log` の節を、上に合わせて直す。

## 実装しないこと

- `--around` で思考を出さないようにするオプション。前後の思考を読まない理由が今のところ無い。必要になったら別の ADR で足す。
- `--around` が無い `show` の既定の変更（思考は出さないまま）。セッションを頭から読むときは、思考を出すと長くなるため。
- 省いたメッセージの代わりに1行を出すこと。
- `search` で思考を対象から外すこと。

## テスト設計

### 関数（`bun test`）

1. 本文が空、または空白だけの思考のブロックは、`thinking: true` でもテキストにならない。本文のある思考は `[thinking] <本文>` になる。

### `chat-log`（`bun test`、コマンド）

2. `show --around N` で、範囲の中の中心以外のメッセージの思考が、`--thinking` なしで出る（[ADR 0013](0013-chat-log-output-corrections.md) のテスト設計2の「中心以外の思考は出ない」を改める）。
3. `--around` なしの `show` では、`--thinking` が無ければ思考を出さない。思考だけのメッセージは省かれる。
4. 本文が空の思考だけからなるメッセージは、`--thinking` を付けても、`--around` の範囲の中でも出ない（見出しも出ない）。本文のある思考とテキストを持つメッセージは、空の思考を除いて出る。
5. `--json` では、空の思考のブロックも出る。
6. ヘルプに、`--around` が範囲のメッセージの思考を出すこと、空の思考を出さないことが出る。

### 手で確かめること

1. 文脈を持たないエージェントに、ヘルプだけを頼りに同じ問い（写しを1回だけ出すことにした理由）を解かせ、`--around` の結果で #424 の思考が読めることと、前後の思考が見えないという報告が出ないことを確かめる。

## トレードオフ

- `--around` の出力が、前後の思考の分だけ長くなる。本文のある思考は少なく（思考のブロックの約 12.5%）、範囲は既定で 10 件、思考は `--max-chars`（既定 2000 文字）で切るので、増える量は限られる。
- `--around` と `--thinking` の関係が、「`--around` では常に思考を出す」になる。`--thinking` は `--around` の無いときだけ意味を持つ。
- 本文が空の思考を出さないため、その思考があったことはテキストの出力から分からなくなる。中身が無いので、読む側に失うものは無い。`--json` では分かる。
