# ADR 0021: chat-log search でツールの入出力も探せるようにする

ステータス: 採択

## 文脈

検索（[ADR 0003](0003-tauri-log-viewer-with-search.md)、[ADR 0011](0011-cli-for-ai-agents.md)）の対象は、メッセージのテキストと思考だけである。ツールの入力（`tool_use`）と結果（`tool_result`）は、検索の索引（`record_texts`）に入れていない。

[ADR 0019](0019-chat-log-thinking-around-hits.md) の実装の後、文脈を持たないエージェントに、ヘルプだけを頼りに過去の決定を探させた。
決定の文面（ADR への追記）は、本文ではなく、ADR を書きかえるツールの入力（置換のスクリプト）の中にしか無かった。
エージェントは「[ADR 0005](0005-log-viewer-corrections-and-details.md)に書き足し」という思考から辿り、`show --tools --max-chars 0` でツールの入力を開いて、ようやく文面を読めた。
コードやドキュメントに書いた内容（ファイルの編集、コマンド、その出力）は、ツールの入出力にしか残らないことが多い。

取り込んだ履歴（2026-10-22 時点、データベースは 3.8 GB）で、大きさを測った。

| 対象 | 件数 | 文字数 |
|---|---|---|
| いまの索引の本文（`record_texts` の中身の表） | — | 23 MB（索引のデータは 44 MB） |
| ツールの入力（`tool_use` の `input` の JSON） | 48,313 | 36 MB（うちファイルの編集・作成が 4,540 件） |
| ツールの結果のうち、文字列のもの | 42,960 | 64 MB |
| ツールの結果のうち、配列のもの（画像の base64 を含む） | 5,352 | 1,079 MB |

画像を含む配列の結果まで索引に入れると、索引がデータベースの大きさに近づく。

## 実装すること

### スキーマ（`schema/0005-tool-texts.sql`）

- FTS5 の表 `record_tool_texts`（`trigram`。`record_texts` と同じ作り）を足す。`rowid` は `records.rowid`。
- 中身は、会話の種類のレコードの、ツールのブロックのテキストを改行でつないだもの。
  - `tool_use`：ツールの名前と `input` の JSON。
  - `tool_result`：`content` が文字列ならその文字列。配列なら、`text` のブロックのテキストだけ（画像などは入れない）。
- 取り出しの規則をビュー `record_tool_text_source` にする（`record_text_source` と同じ形）。
- 移行で、既存のレコードから表を作る。
- 取り込みのたびに、増えた行を `record_texts` と同じように足す（`src/summaries.ts`）。
- スキーマの版は 5 になる。

### `chat-log search --tools`

- `search` に `--tools` を足す。付けると、メッセージの本文（テキストと思考）に加えて、ツールのテキストも探す。
- 1つのレコードについて、本文がすべての語を含むか、ツールのテキストがすべての語を含めば、結果に出す（本文とツールのテキストにまたがる AND にはしない）。
- 3文字未満の語は、これまでどおり全件を走査する（`record_tool_texts` の中身に `LIKE`）。
- ツールのテキストにだけ一致したときは、抜粋をツールのテキストから作り（[ADR 0018](0018-chat-log-snippets-until-and-help.md) と同じ作り方）、抜粋の先頭に `[tool] ` を付ける。
- `--json` の `matched_in` に `"tool"` を加える。
- `--tools` が無いときの結果は変えない。
- `chat-log` が求めるスキーマの版を 5 にする。古いデータベースでは、これまでどおり終了コード2で、取り込みを勧める。
- ヘルプの `search` に、`--tools` と `[tool]` を書く。ヘルプの使う順序の勧めに、本文で見つからないときは `--tools` を試すことを書く。

### ドキュメント

- `docs/specifications.md` のスキーマの表と `chat-log` の節、README を直す。

## 実装しないこと

- 画像などを含む配列のツールの結果を索引に入れること（大きさのため）。配列の中の `text` のブロックだけを入れる。
- GUI の検索でツールの入出力を探すこと（GUI は版 4 以上で動き、`record_tool_texts` を使わない）。
- 本文とツールのテキストにまたがる AND。

## テスト設計

### スキーマと取り込み（`bun test`）

1. 版 4 のデータベースを開くと版 5 に移り、既存のレコードのツールのテキストが `record_tool_texts` に入る。
2. 取り出しの規則：`tool_use` は名前と入力、文字列の `tool_result` はその文字列、配列の `tool_result` は `text` のブロックだけ。画像のブロックは入らない。ツールの無いレコードは入らない。
3. 取り込みで行が増えると、増えた行のツールのテキストが足される。

### `chat-log`（`bun test`、コマンド）

4. ツールの入力にだけある語は、`--tools` が無いと見つからず、あると見つかって `[tool] ` が付く。`--json` の `matched_in` が `["tool"]`。
5. 本文にもツールのテキストにもある語は、`--tools` があっても1件で、`[tool]` が付かない。
6. 3文字未満の語でも `--tools` で見つかる。
7. 語の一部が本文に、残りがツールのテキストにだけあるレコードは、結果に出ない。
8. 版 4 のデータベースでは、`chat-log` が終了コード2で終わる。
9. ヘルプに `--tools`（search）と `[tool]` が出る。

### 手で確かめること

1. 本物のデータベースを移行し、移行の時間と、データベースの大きさの増え方を測る。
2. 文脈を持たないエージェントに、ヘルプだけを頼りに「[ADR 0005](0005-log-viewer-corrections-and-details.md) に書き足した写しの規則の文面」を探させ、`search --tools` で見つけられることを確かめる。

## トレードオフ

- データベースが大きくなる（入れるテキストは約 100 MB。いまの索引の比から、索引は 200〜300 MB と見込む）。移行と、取り込みのたびの索引の更新に時間がかかる。
- ツールの結果には長いログやファイルの中身が多く、`--tools` の結果は雑音が多くなりうる。既定では探さず、`--tools` を付けたときだけにする。
- 配列のツールの結果の画像は探せない。もともと画像は文字で探せない。
