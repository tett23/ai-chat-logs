# ADR 0022: chat-log search に除く語を指定する --exclude を足す

ステータス: 採択（未実装）

## 文脈

`chat-log search`（[ADR 0011](0011-cli-for-ai-agents.md)）は、すべての語を含むメッセージを探す（AND）。語を除く手段は無い。

[ADR 0018](0018-chat-log-snippets-until-and-help.md) と [ADR 0019](0019-chat-log-thinking-around-hits.md) の実装の後、文脈を持たないエージェントに2度、ヘルプだけを頼りに「写しを1回だけ出すことにした理由」を探させた。
どちらでも次のように報告された。

- 「写し」で検索すると、動詞の「写す」（「/Applications に写して」「`.env` に写しても」など）にも一致し、結果の約半分が無関係だった。
- 用語として定義した語（[ADR 0018](0018-chat-log-snippets-until-and-help.md) のヘルプの「用語」）が日常語と同じ形なので、雑音が多い。

日本語の検索は FTS5 の `trigram` と `LIKE` で文字の並びを探すため、語の切れ目で区別できない。
「写し」を含み「写して」を含まないもの、のように、除く語を指定できれば雑音を減らせる。
語の前に `-` を付ける書き方（`-写して`）は、コマンドラインのオプションと区別がつかず、`--` を挟む必要があって間違えやすい。

## 実装すること

- `search` に `--exclude <語>` を足す。何度でも指定できる。
- 結果から、どれか1つの除く語を含むメッセージを除く。除く語を探す対象は、語を探す対象と同じ（本文。`--tools` があるとき（[ADR 0021](0021-search-tool-inputs-and-results.md)）は、一致したテキスト）。
- 除く語の比べ方は、語と同じ（3文字以上は FTS5 の `NOT`、3文字未満は `NOT LIKE`。ASCII の大文字と小文字を区別しない）。
- 除く語は抜粋で強調しない。
- 語を1つも指定せず `--exclude` だけのときは、使い方の誤り（終了コード2）。
- ヘルプの `search` に `--exclude` を書き、例に `chat-log search 写し --exclude 写して --exclude 写す` を足す。用語の節の「写し」に、日常語と同じ形なので `--exclude` かほかの語で絞るとよいことを書く。

### ドキュメント

- `docs/specifications.md` の `chat-log` の節と README を直す。

## 実装しないこと

- 語の前の `-` で除く書き方。
- OR やかっこを使った検索式。
- GUI の検索での除く語。

## テスト設計

### 関数（`bun test`）

1. 検索の計画を作る関数：除く語の、3文字以上は FTS5 の `NOT` の句、3文字未満は `NOT LIKE` の型になる。FTS5 の記号は文字として扱われる。

### `chat-log`（`bun test`、コマンド）

2. 「写し」と「写して」を含むメッセージと、「写し」だけを含むメッセージがあるとき、`search 写し --exclude 写して` は後者だけを出す。
3. 3文字以上の除く語（FTS5）と3文字未満の除く語（`LIKE`）の両方で除ける。複数の `--exclude` は、どれかを含めば除く。
4. 大文字と小文字の違う除く語でも除ける（ASCII）。
5. 抜粋に除く語の強調が無い。
6. 語が無く `--exclude` だけのときは終了コード2。
7. ヘルプに `--exclude` と例が出る。

## トレードオフ

- 除く語は、意味ではなく文字の並びで除く。「写しても」を除くと、それを含む関係のあるメッセージも除かれる。除いたことは利用者が指定したもので、結果から理由が分かる。
- `--exclude` を何度も書く必要がある。`-` を付ける書き方より長いが、オプションと取り違えない。
