# ADR 0023: chat-log show --around の前と続きの行を直す

ステータス: 採択

## 文脈

`chat-log show --around <番号>`（[ADR 0011](0011-cli-for-ai-agents.md)、[ADR 0013](0013-chat-log-output-corrections.md)）は、出力の前後に次の行を出す。

- 範囲が1件目より後から始まったとき、先頭に「（前：#1〜#<数> は --offset 0 で出す）」。
- 範囲の後にメッセージがあるとき、末尾に「（続き：#<次の番号> から。--offset <数> で出す）」。

文脈を持たないエージェントに、ヘルプだけを頼りに過去の決定を探させたところ、次のように報告された。

- 「（前：#1〜#414 は --offset 0 で出す）」に従って `--offset 0` を付けても、出るのは #1 から `--limit` 件である。直前の部分だけを読みたいときは、`--offset` を自分で計算する必要がある（[ADR 0018](0018-chat-log-snippets-until-and-help.md) の後の確認）。
- `--around N --limit 1` で1件だけ出しても、先頭に「前」、末尾に「続き」の行が付き、冗長に感じた（[ADR 0019](0019-chat-log-thinking-around-hits.md) の後の確認）。

`--around N --limit 1` は、`search` の結果の1件を読むための使い方としてヘルプに書いてある（「--limit 1 ならその番号の1件だけ」）。

## 実装すること

- `--around` のときの「前」の行は、範囲の直前の、同じ件数（`--limit`）の範囲を指す：「（前：#<a>〜#<範囲の最初 − 1> は --offset <a − 1> で出す）」。`a` は `範囲の最初 − --limit`（1 より小さければ 1）。
- `--around` で `--limit 1` のときは、「前」と「続き」の行を出さない。
- `--around` が無いときの「続き」の行と、`--limit` が2以上のときの「続き」の行は変えない。
- ヘルプの `show` の、前と続きの行の説明を改める。

### ドキュメント

- `docs/specifications.md` の `chat-log` の節を直す。

## 実装しないこと

- 「前」と「続き」の行に `--around` の形の指定を出すこと（`--offset` で読めるので、書き方を1つにする）。
- `--around` が無いときに「前」の行を出すこと。

## テスト設計

### 関数（`bun test`）

1. 前の行の範囲：範囲が #50〜#59、`--limit` 10 なら #40〜#49 と `--offset 39`。範囲が #6〜#15 なら #1〜#5 と `--offset 0`。範囲が #1 から始まれば出さない。

### `chat-log`（`bun test`、コマンド）

2. `show --around 50` の先頭の行が「（前：#35〜#44 は --offset 34 で出す）」になり（既定の 10 件。範囲は #45〜#54）、その `--offset` と `--limit 10` で #35〜#44 が出る。
3. `show --around 50 --limit 1` は、前と続きの行を出さない。
4. `--around` なしの `show` の続きの行は変わらない。
5. ヘルプに、前の行が直前の範囲を指すことと、`--limit 1` のときに行を出さないことが出る。

## トレードオフ

- `--limit 1` のときは、前後があることが出力から分からなくなる。1件だけを読む使い方なので、前後を読むときは `--limit` を増やす。
- 「前」の行が #1 からの範囲を指さなくなる。最初から読みたいときは `--around` を外して `show` を使う。
