# ADR 0024: GUI の会話の欄の範囲の表示の余白と、ブロックの種類を隠すメニュー

ステータス: 採択（未実装）

## 文脈

GUI（[ADR 0003](0003-tauri-log-viewer-with-search.md)）の会話の欄は、上端に、読みこんだ範囲と総数（`<最初の番号>〜<最後の番号> / <総数>`。[ADR 0014](0014-load-conversations-in-pages.md)）を出す。
この表示は、スクロールしても上端に残るように `position: sticky; top: 0` で置き、会話の欄の内側の余白（16px）に重ねるために、上に −16px の外側の余白を付けている。

利用者から、次の2点を求められた。

1. スクロールが一番上にあるとき、範囲の表示が、最初のメッセージの見出し（役割、モデル、時刻）の文字にかぶる。会話の中身の側の上に余白を付けたい。
2. `tool_use` や `thinking` を隠せるメニューが欲しい。

1 について：利用者の画面の写しでは、一番上までスクロールした状態で、範囲の表示が最初のメッセージの見出しに重なっていた。
範囲の表示の位置は、−16px の外側の余白で会話の欄の内側の余白の上に上げてあるが、`sticky` の要素は、スクロールの領域の内側の余白の内側（上から 16px）に留められるため、一番上でも 16px 下に押し下げられ、続くメッセージに重なると見ている。原因は実装のときに確かめる。

2 について：いまの会話の欄は、テキスト以外のブロック（思考、`tool_use`、`tool_result`、その他）を、畳んだ要素（`details`）として1行ずつ出す。
Claude Code の会話は、ツールの呼び出しと結果が多く、本文を読みたいときには畳んだ行が並んで読みにくい。
`chat-log`（[ADR 0011](0011-cli-for-ai-agents.md)）は、思考とツールを既定で出さないが、GUI には隠す手段が無い。

## 実装すること

### 1. 範囲の表示の下の余白

- 会話の欄で、スクロールが一番上にあるとき、範囲の表示がメッセージに重ならないようにする。
- メッセージを並べる要素の上に余白を付け、範囲の表示の高さの分だけ、最初のメッセージを下げる。
- スクロールしたときは、これまでどおり範囲の表示が上端に残り、その下をメッセージが流れる（半透明の白の背景も変えない）。

### 2. ブロックの種類を隠すメニュー

- 会話の欄の上端の、範囲の表示と同じ行の右に、「表示」のメニューを置く。
- メニューには、次の3つのチェックボックスを並べる。どれも既定では入っている（いまの表示と同じ）。
  - thinking
  - tool_use
  - tool_result
- チェックを外すと、その種類のブロックの畳んだ行を、読みこんだすべてのメッセージで隠す。後から読みこんだメッセージにも効く。
- 隠した結果、出すブロックが1つも無くなったメッセージは、メッセージごと隠す（見出しも出さない）。番号は変えない。
- サブエージェントのメッセージ（畳んだ「サブエージェント」の中）も同じ規則にしたがう。
- テキストのブロックと「その他」のブロック（画像など）は、隠せない。
- 検索の結果から開いたメッセージ（強調するもの）は、隠す種類のブロックしか無くても隠さない。
- チェックの状態は WebView の `localStorage` に保存し、次に起動したときも使う。読めないとき（初めての起動など）は、すべて入っている状態にする。
- 隠したメッセージが多く、表示が画面より短いあいだは、これまでどおり、より古いページを続けて読みこむ（[ADR 0014](0014-load-conversations-in-pages.md)）。

### 書き方

- ブロックとメッセージを出すかどうかを決める関数（メニューの状態とブロックの種類から決めるもの）を、入出力の無い関数として `gui/src/` に置き、`bun test` でテストする。
- メニューの状態の読み書き（`localStorage` の値と状態の変換）も、入出力の無い関数にする。

### ドキュメント

- `docs/specifications.md` の GUI の節と README の GUI の説明を直す。

## 実装しないこと

- 種類ごとに畳んだ行を開いた状態で出す設定。
- 本文が空の思考を隠すこと（[ADR 0019](0019-chat-log-thinking-around-hits.md) の `chat-log` の規則を GUI に持ちこむこと）。
- メニューの状態を設定ファイル（[ADR 0007](0007-settings-and-setup-screen.md)）に保存すること。表示の好みで、CLI と分けあうものではないため。
- 検索の結果を、隠す種類で絞ること。

## テスト設計

### フロントエンド（`bun test`）

1. ブロックを出すかどうか：テキストと「その他」は常に出す。thinking、tool_use、tool_result は、メニューのその種類のチェックが入っているときだけ出す。
2. メッセージを出すかどうか：出すブロックが1つでもあれば出す。無ければ隠す。強調するメッセージは、出すブロックが無くても出す。
3. メニューの状態の読み書き：保存した値から状態に戻せる。値が無い、または形が正しくないときは、すべて入っている状態になる。知らない種類の値は無視する。

### 手で確かめること

1. 会話を開き、一番上までスクロールした状態で、範囲の表示が最初のメッセージの見出しに重ならない。下へスクロールすると、範囲の表示が上端に残る。
2. 「表示」のメニューで tool_use と tool_result のチェックを外すと、畳んだ行が消え、ツールの結果だけのメッセージ（`user` の `tool_result`）が見出しごと消える。チェックを入れなおすと戻る。
3. チェックを外したまま下へスクロールして古いページを読みこむと、読みこんだメッセージにも効いている。
4. GUI を起動しなおすと、チェックの状態が残っている。
5. 検索の結果から tool_result にだけ一致したメッセージを開くと、tool_result のチェックを外していても、そのメッセージは出て強調される。

## トレードオフ

- 範囲の表示の分だけ、一番上のメッセージが下がる。
- 隠したメッセージも読みこむので、隠す種類が多いと、1ページで画面に出る件数が減り、続けて読みこむ回数が増える。
- 状態を `localStorage` に置くため、WebView のデータを消すと既定に戻る。表示の好みなので、失っても困らない。
