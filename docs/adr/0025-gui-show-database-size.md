# ADR 0025: GUI のトップページにデータベースの容量を出す

ステータス: 採択

## 文脈

GUI（[ADR 0003](0003-tauri-log-viewer-with-search.md)）の閲覧の画面は、セッションを開く前の会話の欄に、データベースのパス（`データベース: <パス>`）だけを出す。

データベースは、取り込みを重ねるたびに大きくなる。
[ADR 0021](0021-search-tool-inputs-and-results.md) で、ツールのテキストの全文検索の表を足し、移行でおよそ 580 MB 増えた（2026-10-22 時点で 3.87 GB から 4.45 GB）。
いまの容量を知るには、シェルでファイルの大きさを調べる必要がある。
利用者から、SQLite が使っている容量をトップページに出すよう求められた。

データベースは WAL のモード（[ADR 0001](0001-import-claude-chat-logs-into-sqlite.md)）で開くので、本体のファイル（`<パス>`）のほかに、`<パス>-wal` と `<パス>-shm` がある。
`-wal` は、チェックポイントの前には本体に入っていない変更を持ち、大きくなることがある。

## 実装すること

- GUI の `status` のコマンドの結果に、データベースの容量（バイト数）を足す。本体、`-wal`、`-shm` のファイルの大きさの合計とする。無いファイルは 0 として数える。本体が無いとき、または大きさを読めないときは、容量は無し（`null`）。
- トップページ（セッションを開く前の会話の欄）の表示を、`データベース: <パス>（<容量>）` にする。容量が無しのときは、これまでどおりパスだけを出す。
- 容量の書き方：1000 を単位にして、B、KB、MB、GB、TB のうち、値が 1000 未満になる最も大きい単位で、小数第2位まで（B は整数）。例：`4.45 GB`、`812.30 MB`、`0 B`。macOS の Finder と同じく、1000 を単位にする。
- 容量は、トップページを出すたび（起動したとき、管理画面で設定を保存したとき、取り込みを実行した後）に読みなおす。

### 書き方

- ファイルの大きさの合計を求める関数（パスを受けとり、3つのファイルの大きさを足すもの）を Rust に置き、`cargo test` でテストする。
- 容量の書き方の関数を TypeScript（`gui/src/`）に置き、`bun test` でテストする。

### ドキュメント

- `docs/specifications.md` の GUI の節と、README の GUI の説明を直す。

## 実装しないこと

- 表ごとの容量の内訳（`dbstat` は、データベースの全体を読むため、数秒かかる）。
- 容量の変化を時間を追って出すこと。
- 管理画面の環境の検査（[ADR 0007](0007-settings-and-setup-screen.md)）に容量を足すこと。
- 容量を減らす操作（`VACUUM` など）。GUI はデータベースを読み取り専用で開く（[ADR 0007](0007-settings-and-setup-screen.md)）。

## テスト設計

### GUI のバックエンド（`cargo test`）

1. 本体だけがあるとき、本体の大きさを返す。
2. 本体、`-wal`、`-shm` があるとき、3つの大きさの合計を返す。
3. 本体が無いときは無し。

### フロントエンド（`bun test`）

4. 容量の書き方：0 は `0 B`、999 は `999 B`、1000 は `1.00 KB`、812300000 は `812.30 MB`、4450611200 は `4.45 GB`、1000 の5乗は `1.00 TB`。

### 手で確かめること

1. GUI を起動すると、トップページに `データベース: <パス>（<容量>）` が出て、容量が `ls -l` で見た本体、`-wal`、`-shm` の大きさの合計（1000 を単位に直したもの）と合う。
2. 管理画面で取り込みを実行した後、閲覧の画面に戻ると、容量が新しくなっている。

## トレードオフ

- `-shm` は数十 KB ほどの共有メモリのファイルで、データの容量ではないが、ディスクを使うので合計に入れる。差は小さい。
- 1000 を単位にするので、1024 を単位にする道具（`du -h` など）の値より大きめの数になる。macOS の Finder の表示と合わせることを優先する。
