# ADR 0026: セッションの全文の Markdown への書き出しと、GUI の会話の本文での検索語句の強調

ステータス: 採択（未実装）

## 文脈

利用者から、次の2点を求められた。

1. セッションの全文を書き出したい。GUI と `chat-log`（[ADR 0011](0011-cli-for-ai-agents.md)）の両方から使え、形式は Markdown にする。
2. GUI で、検索の語句を会話の本文の中で強調したい。

いまの状態は次のとおり。

- `chat-log show <ID> --max-chars 0 --thinking --tools --limit <総数>` で、全文に近いものを出せる。ただし、出力は AI が読むための形（[ADR 0013](0013-chat-log-output-corrections.md)）で、本文が空の思考や表示するものの無いメッセージは省く（[ADR 0019](0019-chat-log-thinking-around-hits.md)、[ADR 0020](0020-chat-log-mark-omitted-messages.md)）。ファイルとして残す形にはなっていない。
- GUI には書き出しの機能が無い。
- GUI の検索の結果から会話を開くと、一致したメッセージを枠で囲み、そこまでスクロールする（[ADR 0005](0005-log-viewer-corrections-and-details.md)）。本文のどこが一致したかは示さない。長いメッセージでは、語句を目で探す必要がある。

GUI のバックエンドは Rust、`chat-log` は TypeScript である。
書き出しの Markdown を両方で作ると、同じ規則を2つの言語で持つことになる。
GUI は、取り込みのときにリポジトリのコマンドを `bun` で実行している（[ADR 0007](0007-settings-and-setup-screen.md)）。

## 実装すること

### 1. `chat-log export <セッションID>`

- 1つのセッションの、写しを除いたすべてのメッセージ（[ADR 0005](0005-log-viewer-corrections-and-details.md)）を、番号の順（時刻の順。[ADR 0016](0016-show-conversations-newest-first.md)）に Markdown で標準出力に書く。セッションIDは `show` と同じく、ほかと区別できれば先頭8文字以上でよい。
- `--provider`、`--cwd`、`--since`、`--until`、`--limit`、`--offset`、`--max-chars`、`--json` は受けつけない（使い方の誤り。終了コード2）。
- 形：

  ```
  # <タイトル>

  - セッション: <セッションID>
  - 提供元: <提供元>
  - cwd: <cwd>
  - 期間: <最初の時刻> 〜 <最後の時刻>
  - メッセージ: <件数> 件

  ## #<番号> <役割> <時刻>

  <テキスト>
  ```

  - タイトルが無ければセッションIDを見出しにする。cwd が無ければその行を出さない。
  - サブエージェントのメッセージは、見出しの末尾に ` (サブエージェント)` を付ける。モデルがあれば、時刻の後に ` <モデル>` を付ける。
- ブロックの書き方（メッセージの中のブロックの順を保つ）：
  - テキスト：そのまま。切らない。
  - 思考：本文が空でなければ、`<details><summary>thinking</summary>` と `</details>` で囲み、中は引用（各行の先頭に `> `）にする。本文が空の思考は書かない（[ADR 0019](0019-chat-log-thinking-around-hits.md)）。
  - `tool_use`：`<details><summary>tool_use: <名前></summary>` の中に、入力の JSON を整形して `json` のコードブロックで書く。
  - `tool_result`：`<details><summary>tool_result</summary>`（エラーなら `tool_result（エラー）`）の中に、テキストをコードブロックで書く。配列の結果は、テキストのブロックをつなぎ、画像などは `[<種類>]` にする。
  - その他のブロック：`[<種類>]`。
  - 200文字以上の base64 は、`[base64 <文字数> 文字]` にする（[ADR 0013](0013-chat-log-output-corrections.md) と同じ）。それ以外は切らない。
  - コードブロックの囲みには、中身に含まれるバッククォートの最も長い連続より1つ長いバッククォートを使う（3つ以上）。
- 書くものが1つも無いメッセージ（本文が空の思考だけのものなど）は書かない。番号は詰めない。
- 終了コードは `show` と同じ（セッションが無い・区別できないときは1）。
- ヘルプに `export` を足す。

### 2. GUI の「書き出す」ボタン

- 会話の欄の上端（範囲の表示と「表示」のメニューの行。[ADR 0024](0024-gui-conversation-header-and-block-filter.md)）に「書き出す」ボタンを置く。セッションを開いているときだけ押せる。
- 押すと、保存先を選ぶ画面（`tauri-plugin-dialog` の保存の画面。[ADR 0007](0007-settings-and-setup-screen.md)）を開く。既定のファイル名は `<タイトル>.md`（ファイル名に使えない文字 `/` と `:` は `-` にし、タイトルが無ければセッションID）。
- 保存先を選ぶと、`<AI_CHAT_LOGS_REPO>/src/cli/chat-log.ts export <セッションID>` を、取り込みと同じく `bun` で実行し（`PATH` の先頭に `bun` のディレクトリ、設定の値を環境変数で渡す。[ADR 0007](0007-settings-and-setup-screen.md)）、標準出力を保存先と同じディレクトリの一時ファイルに書いて、終わったら名前を変えて置きかえる。
- 「表示」のメニューの状態（[ADR 0024](0024-gui-conversation-header-and-block-filter.md)）にかかわらず、全文を書く。
- 実行中はボタンを押せなくし、「書き出し中…」と出す。終わったら、成功なら保存先のパスを、失敗なら終了コードと標準エラー出力の最後の20行を出す。失敗したときは一時ファイルを消す。

### 3. GUI の会話の本文での検索語句の強調

- 検索の結果から会話を開いたとき、そのときの検索の語句（入力欄を空白で分けたもの）を、会話の本文の中で強調する（`<mark>`）。一覧から開いたときは強調しない。
- 強調する場所：テキストのブロックと、開いた思考のブロック（コードブロックの中も含む）。ツールのブロック、サブエージェントの見出し、メッセージの見出しは強調しない（GUI の検索の対象が本文と思考だけのため。[ADR 0003](0003-tauri-log-viewer-with-search.md)）。
- 読みこんだすべてのメッセージ（後から読みこんだページも）で強調する。
- 比べ方は検索と同じく、ASCII の大文字と小文字を区別しない。重なる・隣りあう一致は1つにまとめる。
- 一致したメッセージの枠（[ADR 0005](0005-log-viewer-corrections-and-details.md)）は、これまでどおり付ける。
- 別のセッションを一覧から開くか、別の検索の結果から開くと、強調の語句を入れかえる（一覧からなら無し）。

### 書き方

- `chat-log export` の Markdown を作る処理は、入出力の無い関数にして `bun test` でテストする。
- GUI の、テキストを強調の部分に分ける関数と、既定のファイル名を作る関数は、入出力の無い関数にして `bun test` でテストする。
- GUI の、書き出しのコマンドの引数と環境変数を組み立てる処理は、取り込みのもの（[ADR 0007](0007-settings-and-setup-screen.md)）と同じく Rust の入出力の無い関数にして `cargo test` でテストする。

### ドキュメント

- `docs/specifications.md` の `chat-log` と GUI の節、README を直す。

## 実装しないこと

- Markdown 以外の形式（HTML、JSON Lines など。JSON は `show --json` で得られる）。
- 書き出しで、期間や番号の範囲を絞ること。
- 書き出したファイルでの検索の語句の強調。
- `chat-log show` での本文の中の語句の強調（抜粋だけ。[ADR 0013](0013-chat-log-output-corrections.md)）。
- 複数のセッションをまとめて書き出すこと。
- 書き出しの処理を Rust で持ちなおすこと（GUI はリポジトリと `bun` を使う）。

## テスト設計

### `chat-log export`（`bun test`）

1. 関数：見出しとセッションの情報、テキスト、思考（引用と `details`）、`tool_use`（整形した JSON のコードブロック）、`tool_result`（エラーの表示、配列の結果のテキストと `[image]`）、その他、200文字以上の base64 の置きかえ。タイトルと cwd が無いとき。サブエージェントとモデルの見出し。
2. 関数：中身に ``` を含むテキストのコードブロックは、4つのバッククォートで囲む。
3. 関数：本文が空の思考は書かず、書くものが無いメッセージは書かない。
4. コマンド：写しを除き、番号の順に全件を書く（`show` の既定の 50 件を超えるセッションで、全件が出る）。長い本文を切らない。
5. コマンド：先頭8文字のIDで書ける。無いIDは終了コード1。`--limit` などを付けると終了コード2。
6. ヘルプに `export` が出る。

### GUI（`cargo test`、`bun test`）

7. 書き出しのコマンドの組み立て：`bun` と `chat-log.ts export <ID>` の引数、`PATH` の先頭に `bun` のディレクトリ、設定の値が環境変数に入る。
8. 既定のファイル名：タイトルの `/` と `:` を `-` にし、`.md` を付ける。タイトルが無ければセッションID。
9. 強調の分け方：語句の一致を強調の部分に分ける。ASCII の大文字と小文字を区別しない。重なる・隣りあう一致は1つにまとめる。語句が無ければ全体が強調なしの1つ。

### 手で確かめること

1. GUI でセッションを開いて「書き出す」を押し、保存先を選ぶと、Markdown のファイルができる。`chat-log export` の出力と同じ中身になる。
2. 書き出したファイルを Markdown のビューアで開くと、思考とツールが折りたたまれて出る。
3. 検索の結果から開いた会話で、本文の中の語句が強調される。思考を開くと、その中の語句も強調される。下へスクロールして読みこんだメッセージでも強調される。一覧から開きなおすと強調が消える。
4. 大きなセッション（Golem、約8万件）を書き出し、かかった時間とファイルの大きさを測る。

## トレードオフ

- GUI の書き出しは、リポジトリと `bun` に頼る（取り込みと同じ）。Markdown を作る規則を1つにすることを優先する。
- 書き出しは、ツールの結果を切らずに書くので、大きなセッションではファイルが大きくなる（ツールの結果の本文は、データベース全体で 1 GB を超える。[ADR 0021](0021-search-tool-inputs-and-results.md)）。
- 強調は、検索に使った語句の文字の並びで行う。FTS5 の一致と完全には同じにならないことがある（[ADR 0018](0018-chat-log-snippets-until-and-help.md) の抜粋と同じ）。
