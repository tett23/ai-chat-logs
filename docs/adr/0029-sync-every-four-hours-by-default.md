# ADR 0029: 取り込みの既定の間隔を4時間にする

ステータス: 採択

## 文脈

pm2 で `bin/sync` を定期的に実行する間隔は、`ecosystem.config.cjs` の `cron_restart` で決まる（[ADR 0002](0002-periodic-sync-with-pm2.md)）。
値は `AI_CHAT_LOGS_CRON` で、既定は毎時0分（`0 * * * *`）である。
`AI_CHAT_LOGS_CRON` は、環境変数、`.env`、設定ファイルのどれにも書ける（[ADR 0004](0004-load-environment-from-dotenv.md)、[ADR 0007](0007-settings-and-setup-screen.md)）。

利用者から、既定の間隔を4時間にするよう求められた。
利用者の手元では、すでに設定ファイルに `AI_CHAT_LOGS_CRON=0 */4 * * *` を書いて4時間おきにしている（2026-11-07）。

間隔を決める制約は、Claude Code が既定で30日を過ぎた履歴を削除することである（[ADR 0002](0002-periodic-sync-with-pm2.md)）。
4時間はこれより十分に短い。

手元の `runs` 表では、毎時の取り込み（2026-11-07 の 01:00〜04:00 の4回）は1回 3〜12 秒、1回で 3,200〜8,400 件のレコードを足していた。

## 実装すること

- `ecosystem.config.cjs` の `cron_restart` の既定を `0 */4 * * *`（0時から4時間ごとの0分。0、4、8、12、16、20時）にする。
- `AI_CHAT_LOGS_CRON` の扱い（環境変数、`.env`、設定ファイルの順に決まること）は変えない。
- `chat-log` のヘルプの「毎時の取り込みで更新される。最新の1時間ぶんが無いことがある」を、既定では4時間ごとで、最新の4時間ぶんが無いことがある、という説明に改める。
- `docs/specifications.md` と README の既定の間隔の記述（「毎時」と `0 * * * *`）を直す。

## 実装しないこと

- 利用者の手元の設定ファイルの `AI_CHAT_LOGS_CRON` を消すこと。既定と同じ値なので、残しても動きは変わらない。消すかどうかは利用者が決める。
- GUI の管理画面で間隔を変えられるようにすること。
- 起動中の pm2 のアプリを登録しなおすこと。既定の変更は、`pm2 start ecosystem.config.cjs` をやりなおしたときに効く。README にその旨を書く。

## テスト設計

### `bun test`

1. `AI_CHAT_LOGS_CRON` が無いとき、`ecosystem.config.cjs` のアプリの `cron_restart` が `0 */4 * * *` になる（既存のテストの期待を改める）。
2. `AI_CHAT_LOGS_CRON` を環境変数、`.env`、設定ファイルで与えたときの既存のテストは、そのまま通る。
3. `chat-log --help` に4時間ごとの取り込みの説明が出る。

## トレードオフ

- 取り込みの遅れが、最大で1時間から4時間になる。最新の会話を `chat-log` や GUI で読むには、先に `bin/sync` を実行するか、GUI の取り込みのボタンを押す必要が増える。
- 1回の取り込みで足すレコードが、おおよそ4倍になる。毎時で 3〜12 秒だったので、1回が数十秒程度に延びると見ている。実行の回数は4分の1になる。
- 間隔は30日の削除に比べて十分に短いので、取りこぼしの危険はほとんど変わらない。ただし、Mac が止まっていた時間に当たった実行は飛ばされる（pm2 の cron は過ぎた時刻の分を後から実行しない）ため、1回の取り逃しで遅れが4時間ぶん増える。
