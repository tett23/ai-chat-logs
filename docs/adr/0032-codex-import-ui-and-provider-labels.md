# ADR 0032: Codex の取り込み画面とログの提供元の表示

ステータス: 採択

## 文脈

Codex のログを、既存の Claude のログと同じアプリで保存して読みたい。
ChatGPT はエクスポート待ちのため、画面、DB、取り込みを [ADR 0035](0035-import-chatgpt-exports.md) に分ける。
起動中の AI Chat Logs の閲覧画面と管理画面を 2026-11-11 に撮影し、その構成に合わせた画面モックを利用者に示した。
利用者はモックを了承し、管理画面を既存の Claude と同じ形式で実装することを求めた。
提供元の表示は、Claude Code、claude.ai、Cowork を区別する。

この ADR は、提供元の表示、設定、取り込み操作の契約を決める。
DB マイグレーションは [ADR 0033](0033-codex-conversation-database-migration.md)、入力の識別と変換は [ADR 0034](0034-import-codex-rollouts.md) で決める。
Codex の取り込みは ADR 0032、[ADR 0033](0033-codex-conversation-database-migration.md)、[ADR 0034](0034-import-codex-rollouts.md) の採択後に実装する。
[ADR 0035](0035-import-chatgpt-exports.md) の採択や ChatGPT の入力形式の確認を待たない。
画面モックのサンプル件数や成功メッセージは、動作を確認した事実ではない。

既存の管理画面は [ADR 0007](0007-settings-and-setup-screen.md)、ダウンロード済みエクスポートの取り込みは [ADR 0010](0010-scan-downloads-for-claude-ai-exports.md) に従う。
本 ADR は、その構成に Codex を加える。

## 実装すること

### 1. 提供元の表示

「提供元」は、会話を記録したサービスまたはツールを指す。
会話一覧と検索結果の各会話のタイトルの前に、次の表示を付ける。
会話を開いたときのヘッダーにも、同じ表示を出す。
表示はタイトルとは別の要素にし、保存済みのタイトルを書き換えない。

| 記録元 | 表示 |
| --- | --- |
| Claude Code | Claude Code |
| claude.ai | claude.ai |
| Cowork | Cowork |
| Codex | Codex |

会話ヘッダーでも同じ表示名を使い、3種類を「Claude」という表示にまとめない。
既存の内部識別子 `claude-code`、`claude-ai`、`claude-cowork` は変更しない。
未対応の提供元は内部識別子をそのまま表示し、Claude として扱わない。
タイトルが空でも提供元の表示を省かない。

### 2. 閲覧画面

上部の「閲覧」「管理」と検索欄、左側のプロジェクト選択と会話一覧、右側の会話表示を維持する。
文字の大きさ、余白、罫線、ボタンは既存画面のスタイルに合わせる。
提供元ごとの新しいサイドバーやカード型の管理画面は作らない。

プロジェクト選択には「Codex / 作業ディレクトリ」を加える。
Codex は作業ディレクトリごとに絞り、作業ディレクトリが無い会話は「Codex / 作業ディレクトリなし」で選べるようにする。
Claude Code のプロジェクト、claude.ai、Cowork の既存の選択肢を維持する。
同じ作業ディレクトリでも、Codex の選択肢では Claude Code の会話を返さない。
「すべてのプロジェクト」では全提供元を対象とする。

検索、会話の新しい順の表示、ページ単位の読み込み、表示するブロックの選択、Markdown の書き出しは、新しい提供元にも適用する。
実物に無い思考やツールの結果を、通常の本文から作って補わない。

### 3. 管理画面の設定

管理画面は「設定」「環境の検査」「初期化」の順を維持する。
既存の設定行を残し、次の行を、claude.ai の受け取り用ディレクトリの後に加える。
表の `~` はホームディレクトリを表す説明用の記法であり、画面には解決済みの絶対パスを出す。
設定値中の `~` や変数を展開しない既存の規則は変えない。

| 表示名 | 設定キー | 既定 |
| --- | --- | --- |
| Codex のログディレクトリ | `AI_CHAT_LOGS_CODEX_DIR` | `~/.codex` |
| Codex のログの保存先 | `AI_CHAT_LOGS_CODEX_STORE` | `${XDG_DATA_HOME:-~/.local/share}/ai-chat-logs/codex` |

これらは本 ADR で定める設定であり、Codex 自体の設定キーではない。
Codex のログディレクトリの下で探索するファイルは、入力形式を扱う ADR で決める。

各行には、ラベル、設定キー、値の出どころ、入力欄、保存ボタン、いまの値を出す。
値は、環境変数、リポジトリの `.env`、設定ファイル、既定の順に解決する。
GUI が書くのは設定ファイルだけであり、CLI も同じ設定を読む。
空欄の保存では設定ファイルからそのキーを除き、優先順位に従って値を解決し直す。
環境変数や `.env` が優先される場合は、設定ファイルを変えても有効な値が変わらない旨を出す。

「環境の検査」には、新しい2つのパスの存在と種類を加える。
データベース、bun、pm2、launchd を調べる既存の項目は省かない。
検査だけでファイルを作ったり取り込んだりしない。

### 4. 取り込み操作

「初期化」の既存のボタンを維持する。
既存の「取り込む」が実行する `bin/sync` に、Codex のローカルログを加える。
Codex 専用の取り込みボタンは増やさない。
pm2 の実行間隔や登録方法は変えない。

閲覧画面の「ダウンロードしたエクスポートを取り込む」と、管理画面の「claude.ai のエクスポートを取り込む」は、既存の claude.ai 用の表示と操作を維持する。
これらが続けて呼ぶ `bin/sync` でも、Codex のローカルログを取り込む。
ChatGPT のボタン、設定、選択肢は本 ADR の実装では表示しない。
Codex の変換で一部に失敗しても他の入力の取り込みを続け、全体の結果は失敗とする。
元のローカルログは消さず、移動しない。

GUI 全体で取り込みを同時に1つだけ実行する。
実行中は閲覧画面と管理画面の取り込みボタンを無効にし、実行中であることを出す。
終了後は成功または終了コードと詳細出力を示し、取り込みボタンを再び有効にする。
データベースと一覧を読み直し、開いている会話は維持する。
GUI のデータベース接続は読み取り専用のままとし、書き込みは子プロセスの CLI が行う。

### 5. ドキュメント

実装の PR で README と `docs/specifications.md` に、対応する提供元、表示、設定、取り込み手順を追記する。
提案の段階では、未実装の機能を現在の仕様として書かない。
実装開始時に ADR 0032、[ADR 0033](0033-codex-conversation-database-migration.md)、[ADR 0034](0034-import-codex-rollouts.md) の採択を確認する。

## 実装しないこと

- ChatGPT の表示、設定、DB 対応、取り込み。これらは [ADR 0035](0035-import-chatgpt-exports.md) に分ける。
- クラウド上にしか無い Codex の会話の取得。
- GUI の全面的な再設計、提供元ごとの別画面、pm2 の登録操作。
- Claude の既存の内部識別子や保存済みタイトルの変更。
- 本 ADR だけを根拠にした入力パーサ、重複判定、スキーマ変更の実装。

## データ構造

表示名と内部識別子を分離し、表示名の対応表を GUI 内で共用する。
Claude の各記録元を区別し、検索条件と会話の識別にも元の内部識別子を使う。
作業ディレクトリのフィルターは、指定なし、指定したパスとの一致、値なしの3状態を区別する。
既存 API の `cwd: null` は指定なしを意味するため、値なしだけを選ぶ条件には流用しない。
GUI のフィルターと一覧および検索の問い合わせに `cwd_missing` という真偽値を加える。
省略時は偽とし、真なら `cwd IS NULL` で絞る。
真と非 NULL の `cwd` を同時に渡した要求は、入力エラーにする。

Codex の内部識別子と会話の複合キーは [ADR 0033](0033-codex-conversation-database-migration.md)、元データの保存方法は [ADR 0034](0034-import-codex-rollouts.md) で定める。

## 不変条件

1. **I1 提供元の表示**: 表示対象の全会話で、一覧、検索結果、ヘッダーの表示名が対応表と一致し、保存済みタイトルは変わらない。
2. **I2 絞り込み**: 提供元と作業ディレクトリを指定した結果の全会話は、その両方の条件を満たす。
3. **I3 設定の解決**: CLI と GUI の有効な値と出どころは一致し、保存による変更先は設定ファイルだけである。
4. **I4 読み取りだけの検査**: 環境の検査の前後で、設定ファイル、入力ファイル、データベースの内容は変わらない。
5. **I5 実行の排他**: GUI が開始して実行中の取り込み処理の数は、常に0か1である。
6. **I6 結果の表示**: キャンセル時の起動数は0であり、実行した処理に失敗があれば全体を成功と表示しない。
7. **I7 入力の保持**: 取り込みの成否によらず、元の ZIP とローカルログを取り込み処理が削除、移動、上書きしない。

| 境界の入力 | 期待する結果 | 不変条件 |
| --- | --- | --- |
| 会話0件 | 一覧は空。提供元の架空の行を出さない | I1 |
| 各提供元1件、空のタイトル、未対応の提供元 | 定めた表示名または内部識別子を表示。タイトルは不変 | I1 |
| 同じ作業ディレクトリに Claude Code と Codex が各1件 | Codex で絞ると Codex の1件だけ | I2 |
| Codex の作業ディレクトリが無い | 専用の選択肢でその会話を選べる | I2 |
| 設定が無い、設定ファイルだけ、全出どころに値がある | 既定、設定ファイル、環境変数の順に各ケースの値が決まる | I3 |
| 空欄の保存、上位の設定による上書き | キーを除いた後の有効な値と出どころを表示 | I3 |
| 存在するパス、無いパス、読めないパス | 検査結果だけを表示 | I4 |
| 実行中0件、1件、2件目の要求 | 初回は開始、2件目は開始しない | I5 |
| ファイル選択のキャンセル、変換の失敗、一部の変換の失敗 | 未実行、変換失敗、部分的な成功を含む失敗を区別 | I6 |
| 正常な入力、壊れた入力 | 元ファイルを保持 | I7 |

## テスト設計

自動テストは実装より先に書き、失敗を確認する。
テスト名には `I1` から `I7` の対応する番号を含める。
入力形式を必要とするテストは、[ADR 0034](0034-import-codex-rollouts.md) で定める実物由来のフィクスチャを使う。

### GUI の表示（`gui/` で `bun test`）

- I1: 全提供元、未対応の提供元、空のタイトルについて、表示名とタイトルの非変更を確認する。
- I2: プロジェクトの選択肢とフィルターの組を確認する。作業ディレクトリなしの Codex も含める。
- I5: 画面を切り替えても実行状態を共有し、2件目を開始しない。
- I6: 完了、失敗、キャンセルの表示とボタンの復帰を確認する。

### 設定と実行（`cargo test`、ルートで `bun test`）

- I2: GUI の問い合わせが、同じ作業ディレクトリの異なる提供元を混ぜない。指定なし、パス指定、値なしだけの3状態を確認し、`cwd_missing` と非 NULL の `cwd` の同時指定は入力エラーになることを確認する。
- I3: 新しい2つの設定キーについて、全出どころ、空欄の保存、上位の設定を共通の入力例で確認する。
- I4: 一時ディレクトリで環境の検査を行い、検査前後のファイルの内容と一覧を比較する。
- I5、I6: 子プロセスの実行を差し替え、同時実行数、キャンセル時の起動数、claude.ai の手動変換が失敗したときに同期しないことを確認する。Codex の同期内の部分失敗は、他の入力の処理を止めない。
- I6: 一部の変換が失敗しても残りを実行し、最後は失敗を返すことを確認する。
- I7: 正常入力と壊れた入力で、元ファイルのパスとバイト列が変わらないことを確認する。

### 手で確かめること

- I1、I2: Claude Code、claude.ai、Cowork、Codex が混在する一覧と検索結果を開き、ラベル、絞り込み、ヘッダーを確認する。
- I3、I4: 起動中アプリを基準にした構成と、設定行の表示、検査の既存項目が残っていることを確認する。
- I5、I6: 取り込み中に閲覧と管理を切り替え、重ねて起動できないことと、終了後の一覧更新を確認する。
- I7: 実物の入力のコピーで取り込みを行い、元ファイルの保持と提供元を確認する。
- 新しい提供元で、検索、ページ読み込み、表示ブロックの選択、Markdown の書き出しを確認する。

## トレードオフ

すべての会話に提供元を付けるため、一覧のタイトルに使える幅は狭くなる。
Claude Code、claude.ai、Cowork を一覧の時点で区別できる方を選ぶ。

設定を既存の行に追加するため、管理画面は縦に長くなる。
既存の操作方法を維持し、利用者が提供元ごとに異なる操作を覚えずに済む方を選ぶ。

画面の契約と入力形式の決定を分けるため、この ADR だけでは取り込みの実装を始められない。
実物を確認せずに保存形式や重複判定を決めることを避ける。
