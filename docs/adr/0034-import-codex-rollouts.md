# ADR 0034: Codex のローカルログを取り込む

ステータス: 採択（未実装）

## 文脈

[ADR 0032](0032-codex-import-ui-and-provider-labels.md) の画面と [ADR 0033](0033-codex-conversation-database-migration.md) のスキーマに、新しい入力を渡す処理を定める。
入力の列挙、形式の変換、DB への取り込みを小さなコマンドに分け、GUI と定期実行から同じ処理を呼ぶ。

2026-11-11 に、`~/.codex/sessions` の JSONL 16ファイルを読み、JSON のキーと種類を集計した。
`archived_sessions` には JSONL が無かったため、その探索は未検証である。
本文は ADR に転記しない。
集計した時点で `session_meta` は18行あり、`payload.id` と `payload.session_id` の値が異なるものは5行あった。
サブエージェントのファイルに、そのエージェントのメタデータの後で親のメタデータが入る例もあった。
ファイル名の ID は先頭の `session_meta.payload.id` と一致していた。
この観察を根拠に、ファイルの所有者は先頭のメタデータから決め、後続のメタデータで切り替えない。

観察した `response_item` の種類は、`message`、`reasoning`、`function_call`、`function_call_output`、`custom_tool_call`、`custom_tool_call_output`、`agent_message`、`additional_tools` である。
`message` には user、assistant、developer の role があり、content には input_text、output_text、encrypted_content があった。
`event_msg` にも完了した項目や最後の応答を含む記録があるため、両方を本文として取り込むと二重に表示しうる。

ChatGPT の取り込みは [ADR 0035](0035-import-chatgpt-exports.md) に分ける。
本 ADR の採択と Codex の実装は、ChatGPT のエクスポート取得を待たない。

## 実装すること

### 1. コマンドと処理の分割

| コマンド | 入力 | 出力と役割 |
| --- | --- | --- |
| `codex-log-convert` | 設定した Codex のログディレクトリ | 元ログの保存用コピーと共通形式の JSONL を作る |
| `codex-log-sources` | Codex の保存用ディレクトリ | `codex/rollout` と `codex/conversation` のパスを列挙する |

列挙の出力は既存と同じ `<種類>\t<絶対パス>` とする。
DB への取り込みは既存の `chat-log-import` を拡張し、変換コマンドから DB に書かない。
TypeScript ではクラスを使わず、パース、変換、ID の計算を入出力の無い関数にする。

`bin/sync` とインストール済みの同期コマンドで、既存の claude.ai のスキャンと Codex の変換を行った後、全提供元の列挙結果をまとめて1回取り込む。
列挙の失敗時には `--mark-missing` 付きの取り込みを開始しない。
スキャンまたは変換の一部が失敗しても、公開済みの保存用ファイルと他の提供元を取り込み、最後の終了コードは1にする。
全成功は0、設定や引数の誤りは2とする。

新しいコマンドは `bin/install` の対象に加える。
既存のコマンド名と引数は維持する。
新しい設定は [ADR 0032](0032-codex-import-ui-and-provider-labels.md) に従い、Codex の保存先として `AI_CHAT_LOGS_CODEX_STORE` を追加する。
既定は `${XDG_DATA_HOME:-~/.local/share}/ai-chat-logs/codex` とし、GUI の設定と環境の検査でも扱う。

### 2. 保存と公開

変換元を識別するハッシュは SHA-256 の64桁すべてを使う。
改行まで完成した Codex の入力のバイト列をハッシュ化する。
保存先は `<保存用ディレクトリ>/<ハッシュ>/` とし、元データ、`messages-v1.jsonl`、`manifest-v1.json` を置く。
同じハッシュの保存先が公開済みなら再変換しない。
原本を変更せず、変換規則の更新は出力名の版を上げる別 ADR で決める。

一時ディレクトリに原本と変換結果を書き、検証してからディレクトリの rename で公開する。
列挙は manifest がある完成済みのディレクトリだけを対象にする。
同じ入力の並行変換では、一方の公開済みディレクトリを利用し、もう一方の一時出力は破棄する。
公開済みファイルを上書きしない。
ディレクトリは0700、保存ファイルは0600で作る。
manifest には変換器の版、原本のハッシュ、元のパス、会話数、変換行数、警告の件数と変換の終了コードを保存する。
元のパスだけが変わった場合は、同じ入力として既存の保存先を利用する。

Codex の入力が伸びた場合は、その時点の完成した行までを別のスナップショットとして保存する。
スナップショットとは、ある時点までの入力を固定した保存用コピーである。
重複する原本行も保存されるが、閲覧用の写しはメッセージ ID により除く。
初版ではスナップショット間の差分保存をしない。
長いログでは容量と変換時間が増えるため、実装時に手元の最大ログで測定し、結果を採択後の実装 PR に記録する。

### 3. 共通形式と重複

共通形式は既存の Claude の変換形式に合わせる。
1つの表示項目を `type: user|assistant`、`sessionId`、`uuid`、`timestamp`、`cwd`、`sourceOrder`、`message: { role, content }` で表す。
ブロックは text、thinking、tool_use、tool_result を使う。
元の入力位置、元 ID、親 ID、role、channel、版の識別情報は `openai` に残す。
元データそのものは、保存用コピーから参照できるようにする。

`uuid` は、正規化した JSON の SHA-256 とする。
対象は、提供元、会話 ID、元の項目 ID、表示する内容、元の role、親 ID、ブロックの種類である。
JSON のオブジェクトキーは辞書順、配列は元の順とし、ファイルパス、取り込み時刻、スナップショットのハッシュは含めない。
元の項目 ID が無い場合は、Codex では先頭からの物理行番号を代わりにする。
同じ入力の同じ項目は同じ uuid となり、別の項目に同文があっても統合しない。
同じ元 ID で表示内容が変わった場合は別の版として両方残し、会話表示と Markdown の各項目に元 ID と版のハッシュの先頭12桁を表示し、別の版であることを区別する。
内容の同じ写しだけを除き、編集前の版は消さない。

不明な形式は、本文へ推測で変換しない。
原本を保存し、入力位置と未対応の種類を警告として出す。
暗号化された内容は復号も推測もせず、表示できない項目として位置を示す。
未知の項目は会話の件数に加えず、表示できない暗号化項目は元 ID ごとに1項目として数える。

### 4. Codex の入力

`AI_CHAT_LOGS_CODEX_DIR` の `sessions` と `archived_sessions` 以下にある通常ファイル `*.jsonl` を再帰的に調べる。
シンボリックリンクは辿らず、認証情報や設定ファイルは対象にしない。
存在しないディレクトリは空として成功し、読めないディレクトリは失敗として報告する。

先頭の `session_meta.payload.id` を会話 ID とする。
`payload.session_id` は会話 ID の代わりに使わず、親との関係を確認するため原本に残す。
空ファイルは0行の原本と0会話として保存し、成功にする。
空でないファイルの先頭のメタデータに有効な ID が無い場合は、原本だけ保存し、表示用の変換は失敗として報告する。
後続のメタデータで会話の所有者を変えない。
サブエージェントの会話は別会話にし、親の会話へ自動で統合しない。
継承された親の履歴も、そのファイルにある記録として保持する。

作業ディレクトリは先頭のメタデータの `cwd` とする。
無い場合は null とし、後続の `turn_context` の値で推測しない。
タイトルは最初の通常の user 本文の先頭80文字とし、本文が無ければ会話 ID とする。
時刻は外側の `timestamp` を使い、無い場合は null とする。
変換行の `sourceOrder` に元の物理行番号を入れ、出力行も元の順に並べる。
1つの response_item からは、複数のブロックがあっても変換行を1行だけ作る。
表示順は [ADR 0033](0033-codex-conversation-database-migration.md) の共通規則に従う。
タイトルは `type: custom-title`、`sessionId`、`customTitle` の行で出力し、会話の件数には加えない。

| 入力 | 共通形式への変換 |
| --- | --- |
| response_item / message、role=user または assistant | input_text と output_text の text を text ブロックにする |
| response_item / reasoning | 公開された summary の文字列だけを thinking にする。暗号化部分は表示できない旨を出す |
| response_item / function_call、custom_tool_call | assistant の tool_use。name と call_id を残す。arguments または input は元の文字列を保持する |
| response_item / function_call_output、custom_tool_call_output | user の tool_result。call_id があれば対応付け、無ければ独立した結果として示す |
| response_item / agent_message | author、recipient を付けたエージェント間通信として assistant の text にする。content の公開されたテキストを使う |
| message の system、developer、additional_tools | 原本のみ。会話本文にしない |
| event_msg、world_state、turn_context、使用量、その他 | 原本のみ。response_item の代替として本文を作らない |

tool_use の input は文字列をそのまま格納できる `{"raw": "元の文字列"}` とし、JSON として再解釈して情報を落とさない。
対応する呼び出しが無いツール結果も保存する。
追加のキー調査では、`reasoning.summary` は配列で、その要素に `type: summary_text` と `text` があった。
この text を配列の順に thinking ブロックにする。
`agent_message.content` も配列で、`type: input_text` と `text`、または `type: encrypted_content` と `encrypted_content` があった。
前者を text ブロック、後者を表示できない旨の text ブロックにする。
フィクスチャにはこの構造を保ち、未知の形は警告にする。
未知の型や暗号化に関する警告だけなら終了コード0とし、JSON の破損や必要な識別情報の欠落は終了コード1とする。

未完の末尾行は次の実行まで待ち、完成した行だけをスナップショットに含める。
完成した行の JSON が壊れている場合は原本に残し、その行を変換せず、警告と終了コード1を出す。
他の正常な行は変換する。
既存の同じスナップショットを再利用するときも、manifest の失敗状態を返す。
読み取り中に既存部分が変化した場合は公開を中止し、次の実行で再試行する。
読み取り前後のサイズと更新時刻の比較に加え、取得した範囲を再読してハッシュの一致を確認する。
末尾への追記だけなら、取得済みの完成した行を公開してよい。

### 5. 実装の順序と文書

1. [ADR 0032](0032-codex-import-ui-and-provider-labels.md) の表示と設定のテストを書く。
2. [ADR 0033](0033-codex-conversation-database-migration.md) の移行と複合キーのテストを書き、実装する。
3. 本 ADR の変換、列挙、同期のテストを書き、実装する。
4. GUI の操作、インストールするコマンド、README、仕様書を更新する。

これらは採択後の手順であり、本提案作成時にはコードを変更しない。
各段階で既存の Claude の取り込みテストを維持し、新しい機能と一緒に通す。

## 実装しないこと

- クラウド上の会話の取得、ログインの自動化、エクスポート要求の自動化。
- 暗号化された内容の復号、記録に無い本文や思考の補完。
- Codex のイベントと response_item の両方を本文にして数えること。
- 変換済みデータから原本を再現したとみなすこと。
- 元ファイルの削除、スナップショットの自動削除、差分だけを保存する最適化。

## 不変条件

1. **P1 原本の保持**: 公開した原本のバイト列は、入力として確定した完成済み JSONL の範囲と一致する。
2. **P2 決定性**: 同じ変換器の版と入力からは、同じ JSONL と uuid が得られる。
3. **P3 項目の区別**: 同文の異なる元 ID は別項目となり、同じ元 ID と同じ内容の写しは同じ uuid になる。
4. **P4 会話の所有者**: Codex の全変換行の sessionId は、先頭のメタデータの id と一致する。
5. **P5 二重計上の防止**: event_msg の追加だけでは、会話の変換行数は増えない。
6. **P6 公開の原子性**: 列挙される保存先は、原本、変換結果、manifest が揃っている。
7. **P7 部分失敗の報告**: 正常な独立入力の処理を続けても、失敗が1つあれば終了コード1を返す。

| 境界の入力 | 期待する結果 | 不変条件 |
| --- | --- | --- |
| 完全な1行、末尾の未完行、改行が追加された行 | 完成した範囲だけ保存し、次回に追加分を処理 | P1 |
| 同じ入力を2回、別パスの同じ入力 | 同じ保存先と同じ uuid | P2 |
| 同じ本文の2 ID、同じ ID の同文、同じ ID の変更後の本文 | 別項目、同じ写し、別の版 | P3 |
| id と session_id が異なる、後続に親のメタデータがある | 先頭の id を全行で使用 | P4 |
| response_item と同じ応答を含む event_msg | 本文として1回 | P5 |
| 空ファイル、メタデータのみ、メタデータなし | 0行成功、0会話成功、原本保存と変換失敗 | P1、P4 |
| 書き込み途中の停止、公開の競合 | 不完全な保存先を列挙しない | P6 |
| 正常と壊れた入力が各1つ、正常行と壊れた行が混在 | 正常分を保持し、終了コード1 | P7 |

## テスト設計

テスト名に `P1` から `P7` を含め、実装前に失敗を確認する。
実物の本文や認証情報をコミットせず、構造を保った匿名化フィクスチャを作る。

- P1、P2: スナップショットのハッシュ、原本バイト列、変換出力、再実行時の公開数を `bun test` で比較する。
- P3: 異なる ID の同文、同じ ID の再出現、内容の変更を変換し、DB の会話件数と検索件数を確認する。
- P4: 親とサブエージェントのメタデータ、1ファイルの複数メタデータをテストする。
- P5: 同じ応答の response_item と event_msg、公開された思考と暗号化された内容、対応する呼び出しが無いツール結果を確認する。
- P6: 保存処理の各段階で失敗させ、未完成のファイルが列挙されないことを確認する。並行実行も含める。
- P7: スキャン、変換、列挙、取り込みをそれぞれ失敗させ、終了コードと残りの実行を確認する。列挙失敗時は missing_since を変えない。
- `bin/install` のテストで、新しい全コマンドとインストール済み同期コマンドが同じ設定を読むことを確認する。
- 手動: Codex の長いログと追記中のログで、時間、保存容量、原本との一致を測る。

## トレードオフ

固定した原本と変換結果を残すため、Codex の長い会話ではスナップショット間に大量の写しが生じる。
初版では、再実行と障害復旧の単純さを優先する。
容量と速度の改善は、実測を基に別の ADR で決める。

ChatGPT の実物待ちを別の ADR に分けるため、Codex の実装を先に進められる。
ChatGPT を後から追加するときは、採択済みの本 ADR を書き換えず、後続の移行と変換を追加する。
