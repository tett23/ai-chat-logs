# ADR 0035: ChatGPT のエクスポートを取り込む

Status: accepted-pending

## 文脈

ChatGPT のエクスポートは未取得であり、内部形式を確認できていない。
利用者の指示により、Codex の取り込みを先に進め、ChatGPT の画面、DB 移行、変換、同期は本 ADR に分離する。
本 ADR は実物待ちの提案であり、採択前に入力形式とマイグレーションを補完する。
[ADR 0032](0032-codex-import-ui-and-provider-labels.md)、[ADR 0033](0033-codex-conversation-database-migration.md)、[ADR 0034](0034-import-codex-rollouts.md) の採択と実装は、本 ADR に依存しない。

## 実装すること

### 1. 画面と設定

会話一覧、検索結果、ヘッダーに「ChatGPT」を表示する。
プロジェクト選択には「ChatGPT」を加え、作業ディレクトリで分けない。
Claude Code、claude.ai、Cowork、Codex の既存の表示を維持する。
既存と同じ検索、ページ読み込み、表示ブロックの選択、Markdown の書き出しを提供する。

管理画面の「設定」「環境の検査」「初期化」の構成を維持し、次を既存と同じ形式で追加する。
設定の優先順位、空欄の保存、上位の設定による上書きの表示は [ADR 0032](0032-codex-import-ui-and-provider-labels.md) と同じにする。

| 表示名 | 設定キー | 既定 |
| --- | --- | --- |
| ChatGPT のエクスポートの保存先 | `AI_CHAT_LOGS_CHATGPT_DIR` | `${XDG_DATA_HOME:-~/.local/share}/ai-chat-logs/chatgpt` |
| ChatGPT のエクスポートの受け取り用のディレクトリ | `AI_CHAT_LOGS_CHATGPT_INBOX` | `~/Downloads` |

「初期化」に「ChatGPT のエクスポートを取り込む」を加える。
ZIP の選択をキャンセルした場合は何も実行せず、変換に失敗した場合は同期しない。
閲覧画面の「ダウンロードしたエクスポートを取り込む」は、claude.ai と ChatGPT の両方を対象にする。
提供元ごとの受け取り用ディレクトリと結果を出し、新しく変換したエクスポートの数を件数として表示する。
一方のスキャンが失敗しても他方とローカルログの取り込みを続け、全体の結果は失敗とする。
GUI 全体の取り込みの排他、詳細出力、一覧更新、開いている会話の維持は [ADR 0032](0032-codex-import-ui-and-provider-labels.md) に従う。

### 2. コマンド、保存、DB の後続移行

`chatgpt-export-convert`、`chatgpt-export-scan`、`chatgpt-log-sources` を追加する。
列挙は `<種類>\t<絶対パス>` を出力し、既存の `chat-log-import` で取り込む。
`bin/sync` とインストール済み同期コマンドにスキャンと列挙を加え、`bin/install` の対象にも追加する。

ZIP 全体の SHA-256 の64桁を保存先の名前に使い、原本 ZIP、変換 JSONL、manifest を保存する。
保存先は `AI_CHAT_LOGS_CHATGPT_DIR` の下に作る。
原本保持、原子的な公開、0700/0600の権限、再実行時の再利用は [ADR 0034](0034-import-codex-rollouts.md) と同じ契約を使う。
変換行の uuid、版の保持、会話の複合キーは [ADR 0033](0033-codex-conversation-database-migration.md) と [ADR 0034](0034-import-codex-rollouts.md) の規則を基準に、実物の分岐と ID の構造に適用できるかを確認する。

DB はスキーマ7の後の独立したマイグレーションで拡張する。
Codex の実装で追加する `schema/0007-codex-conversations.sql` は、ChatGPT の追加時に変更しない。
新しい種類は `chatgpt/export` と `chatgpt/conversation`、提供元は `chatgpt` とする案であり、実物の確認後に確定する。
原本 ZIP は `blobs` と `file_versions`、変換行は `records` に保存する案とする。
会話、本文、ツールのビューと写し判定に新しい種類を追加し、既存の行、索引、要約を保持する。
移行番号、SQL の具体的な変更、必要なスキーマ版は、本 ADR の採択時に確定する。
ChatGPT の `sourceOrder` と分岐表示も、実物を確認して定める。

### 3. 入力形式と採択前の確認

エクスポートの ZIP を原本として丸ごと残す。
ZIP 内のファイルを任意のパスへ展開せず、必要なエントリーのバイト列を読み取る。
絶対パス、`..`、同じ正規化名の重複、シンボリックリンクを含むエントリーは拒否する。
変換ファイル名に会話 ID や ZIP 内のパスをそのまま使わない。

採択前に、次を実物で確かめて本節に追記する。

| 確認するもの | 決める規則 |
| --- | --- |
| 会話を含むファイル名、最上位の構造 | claude.ai や無関係の ZIP と区別する判別述語 |
| 会話 ID、タイトル、メッセージ ID | 共通形式への対応と、ID が無いときの失敗範囲 |
| 親子関係、現在の分岐、編集前の版 | 全分岐の保存と表示上の識別。分岐を一本道に見せない |
| role、本文、ツール、思考、添付 | 共通ブロックへの対応と、原本だけに残す範囲 |
| 時刻と単位、値の欠落 | ISO 8601 への変換と、時刻なしの並び順 |
| 添付の実体と参照 | ZIP 内の保存位置と、添付が無い場合の表示 |
| 同じ会話を含む2回のエクスポート | 写しの除去と変更前の版の保持 |

変換の採択条件は、上表の全項目に具体的な規則と匿名化したフィクスチャがあることである。
公式ヘルプだけから内部形式を推定して表を埋めない。
最初のエクスポートだけでは比較できない項目は、2回目の入力を取得して確認する。

### 4. エクスポートの識別とスキャン

受け取り用ディレクトリ直下の ZIP を名前順に調べる。
下位のディレクトリは探索しない。
ChatGPT の追加後は、claude.ai も `conversations.json` という名前だけで判別しない。
既存の claude.ai の構造と、前節で確認した ChatGPT の構造を別々の述語で判定する。
両方に一致する場合は曖昧な入力として拒否し、どちらの変換も行わない。
空の JSON 配列だけでは提供元を判定できないため、自動スキャンではスキップする。
手動で提供元を指定した空のエクスポートは、対応形式の検証を通る場合だけ0会話として保存する。

無関係の ZIP はスキップし、壊れた ZIP はエラーを報告して次へ進む。
ZIP の名前や保存場所だけで提供元を決めない。
同じ受け取り用ディレクトリを両提供元に指定しても、1つの ZIP を両方に変換しない。
何件取り込んだかは、新しく公開した保存先の数で数える。

### 5. 文書と実装開始の条件

本 ADR の未確定事項を埋め、精読と人間のレビューを受けてから採択する。
ChatGPT のフィクスチャに基づくテストを先に書いて失敗させ、後続の DB 移行、変換、GUI、同期の順で実装する。
README と仕様書は実装の PR で更新し、未実装の機能を現在の機能として記載しない。

## 実装しないこと

- 本 ADR の採択を Codex の実装の前提にすること。
- 内部形式を推測したパーサの先行実装。
- エクスポートの要求、ログイン、ダウンロードの自動化。
- 元 ZIP の削除、移動、上書き。

## 不変条件

1. **G1 識別**: 1つの ZIP を claude.ai と ChatGPT の両方として変換しない。
2. **G2 再取り込み**: 同じエクスポートを再取り込みしても、表示上の会話とメッセージの件数は増えない。
3. **G3 原本保持**: 保存した ZIP のバイト列は入力と一致し、入力を変更しない。
4. **G4 既存データ保持**: 後続移行の前後で Claude Code、claude.ai、Cowork、Codex の記録、検索結果、会話の件数は一致する。
5. **G5 実行結果**: 選択キャンセル時は処理を開始せず、一部の取り込みが失敗したときに全体を成功と表示しない。

| 境界の入力 | 期待する結果 | 不変条件 |
| --- | --- | --- |
| claude.ai と ChatGPT が各1 ZIP、同じ受け取り先 | 対応する変換器だけが処理する | G1 |
| 無関係、両形式に一致、空配列だけ | スキップ、拒否、識別不能としてスキップ | G1 |
| 同じ ZIP を1回、2回、別パスから投入 | 表示の件数は不変 | G2 |
| 正常な ZIP、壊れた ZIP | 元ファイルを保持 | G3 |
| スキーマ7の空DB、既存各提供元1件、圧縮済み本文 | 既存データを保持して移行 | G4 |
| キャンセル、変換失敗、片方のスキャン失敗 | 未実行と失敗を区別 | G5 |

## テスト設計

テスト名に G1 から G5 を含め、入力形式の確定後に匿名化した実物由来のフィクスチャで実装前の失敗を確認する。

- G1: 手動と自動で判別述語を共用し、同じ受け取り先でも二重変換しない。
- G2: 同じ ZIP と、同じ会話を含む2回のエクスポートで写しの除去を確認する。
- G3: 正常入力、異常入力、変換中断の前後で元 ZIP のハッシュを比較する。
- G4: 後続移行の前後で全既存提供元の rowid、復元 raw、検索結果、件数を比較する。
- G5: GUI のキャンセル、変換失敗、スキャンの部分失敗、実行中の排他を確認する。
- 手動: 分岐、編集前後、添付、時刻なしの実物を確認し、変換規則とテストを補完する。

## トレードオフ

ChatGPT の実物待ちを分けることで、確認済みの Codex の実装を先に進められる。
DB の移行は別々になるが、未確認の形式に合わせて Codex の実装を仮決めする必要がなくなる。
