# ADR 0036: Codex のログを1時間ごとに収集する

ステータス: 採択（未実装）

## 文脈

利用者から、Codex のコンテキスト圧縮が早いため、ログを1時間ごとに収集するよう依頼された。
収集間隔を短くして、手元にあるログを保存する機会を増やす。
コンテキスト圧縮によりローカルの原本が消えることは確認しておらず、この変更が圧縮前の全履歴の保存を保証するとは扱わない。

[ADR 0029](0029-sync-every-four-hours-by-default.md) は全体の取り込みを4時間ごととし、[ADR 0034](0034-import-codex-rollouts.md) はその取り込みに Codex を加えた。
本 ADR は全体の4時間間隔を維持し、Codex 専用の毎時収集を追加する。

2026-11-11 に、本 ADR の作成より先に利用者の環境へ運用設定を適用した。
pm2 の `ai-chat-logs-codex-sync` に `/bin/sh -c` で既存の変換、列挙、取り込みを登録し、`pm2 save` で永続化した。
初回は `run=656 sources=250 records=47958 blobs=0 errors=0`、終了コード0だった。
本 ADR 作成時の `pm2 jlist` でも、次の登録を確認した。
提案というステータスはレビュー前であることを表し、手元の設定が未適用であることを意味しない。

| pm2 の名前 | cron | 対象 |
| --- | --- | --- |
| `ai-chat-logs-sync` | `0 */4 * * *` | 全提供元 |
| `ai-chat-logs-codex-sync` | `30 * * * *` | Codex のみ |

リポジトリの基準コミットは `408c7ef85584298d46a3c6a8592f996ed3a569d5` である。
この時点の `ecosystem.config.cjs` は全体のジョブだけを定義している。
採択後は、手元だけにある設定を再現できるようにコードと文書へ反映する。

## 実装すること

### コマンドと定期実行

`bin/sync-codex` とインストール済みの `ai-chat-logs-codex-sync` を追加する。
前者はリポジトリの Bun CLI、後者は同じインストール先の実行ファイルを使う。
両方とも次の処理を行う。

1. `codex-log-convert` で原本と変換結果を保存する。
2. `codex-log-sources` の出力を全件取得する。
3. 列挙が成功した場合だけ、取得した一覧を `chat-log-import` に渡す。

Codex だけの一覧には `--mark-missing` を付けない。
専用コマンドは引数を受け付けず、DB を含む設定は既存の環境変数、`.env`、設定ファイルから読む。
引数があれば副作用を起こす前に終了コード2とし、`--mark-missing` の持ち込みを防ぐ。

変換に失敗しても公開済みのスナップショットを列挙して取り込み、最後は終了コード1にする。
列挙が失敗したら取り込みを開始せず、終了コード1にする。
取り込み失敗も1、全成功は0とする。
CLI の設定読み込みに由来する終了コード2も、開始済みの同期処理の失敗として1に集約する。
リポジトリ用コマンドで Bun が見つからない場合は既存の `bin/sync` と同じ127とする。

`ecosystem.config.cjs` に `ai-chat-logs-codex-sync` を追加する。
`script` は `bin/sync-codex`、`autorestart` は false、cron の既定は毎時30分の `30 * * * *` とする。
`AI_CHAT_LOGS_CODEX_CRON` で間隔を変更でき、値の優先順位は既存の `AI_CHAT_LOGS_CRON` と同じにする。
全体のジョブと `AI_CHAT_LOGS_CRON` は変更せず、全体の取り込みでも Codex を扱い続ける。

30分ずらすのは、通常の運用で全体のジョブと開始時刻を重ねないためである。
長時間の処理や手動実行による重なりを排除するものではない。
公開の競合は既存のスナップショット公開規則、DB の競合は既存の SQLite トランザクションと待機時間で扱い、失敗は成功として隠さない。

### 適用と文書

`bin/install` に専用コマンドを加える。
採択後の実装 PR で README、仕様書、`.env.example`、`chat-log --help` を更新し、全体は4時間ごと、Codex は追加で毎時30分という違いを記す。
停止中やスリープ中の実行、長時間の処理、失敗時には、最新1時間分が必ず保存されるという保証はしない。

手元の既存の専用ジョブは処理終了を待ってから削除し、同じ名前で ecosystem の定義から登録し直して `pm2 save` する。
全体ジョブは削除しない。
初回の終了コード、DB の取り込み結果、保存した cron を確認する。
専用収集を元に戻す場合は、専用ジョブだけを削除して `pm2 save` し、全体の4時間ごとの収集は残す。

## 実装しないこと

- Codex 自体のコンテキスト圧縮、保持期間、ログ出力形式の変更。
- Claude の収集間隔の変更、全体ジョブからの Codex の除外。
- macOS の Downloads の権限変更や、claude.ai の受け取り先の変更。
- スナップショットの削除、差分保存、独自のスケジューラや実行ロックの追加。

## 不変条件

1. **H1 対象の分離**: 専用収集が列挙して取り込む種類は `codex/rollout` と `codex/conversation` だけであり、Claude のスキャンと列挙を呼ばない。
2. **H2 不在判定の保護**: 専用収集では新たな不在時刻を付けず、Codex 以外の `missing_since` は変わらない。列挙された Codex が再び存在した場合に既存の不在時刻を NULL に戻す動作は維持する。
3. **H3 失敗の伝播**: 変換または取り込みが失敗すれば全体は1を返し、列挙失敗時は取り込みを0回実行する。
4. **H4 間隔の独立**: 既定では全体が `0 */4 * * *`、Codex が `30 * * * *` であり、一方の cron の指定は他方を変更しない。
5. **H5 再実行**: 同じ入力を専用収集と全体収集で繰り返しても、Codex の論理メッセージの件数は増えない。

| 境界の入力 | 期待する結果 | 不変条件 |
| --- | --- | --- |
| Codex 入力が0件、1件 | 他提供元に触れず終了0 | H1、H2 |
| Claude の既存 source があり、Codex だけを列挙 | Claude の `missing_since` は不変 | H2 |
| 変換失敗、列挙失敗、取り込み失敗 | 継続範囲と終了コードが上記の規則に一致 | H3 |
| cron 指定なし、片方だけ指定、両方指定 | それぞれの設定だけが反映される | H4 |
| 同じ入力を1回、2回、全体収集との並行実行 | 表示上の重複は増えず、失敗した場合は非0終了 | H5 |
| 引数なし、未知の引数、`--mark-missing` | 通常実行、実行前に2、実行前に2 | H2、H3 |

## テスト設計

H1 から H5 をテスト名に含め、実装前に失敗させる。

- H1、H2、H3: コマンドを差し替え、呼び出し順、引数、標準入力、終了コードを両方の専用コマンドで検証する。列挙の部分出力を取り込まないことも確認する。
- H2、H5: Claude と Codex を持つ実 DB フィクスチャで、専用収集、全体収集、再実行、並行実行の後の件数と `missing_since` を比較する。
- H4: ecosystem の2ジョブ、環境変数、`.env`、設定ファイルの優先順位を検証する。
- H1、H3: インストールしたコマンドが Bun なしで動くことと、Claude のスキャンが失敗する環境でも専用収集が成功することを確認する。
- 手動: dev で専用収集を1回実行してから、手元の既存ジョブを置き換える。`pm2 jlist`、`dump.pm2`、終了コード、`runs` を確認する。

## トレードオフ

収集回数を増やすため、追記中のログの全体スナップショットが増え、保存容量と索引処理の負荷が増す。
[ADR 0034](0034-import-codex-rollouts.md) の原本保持と再実行の単純さを維持し、容量の最適化は別の変更として検討する。
