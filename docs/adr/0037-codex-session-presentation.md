# ADR 0037: Codex の会話一覧と暗号化項目の表示を整理する

ステータス: 採択

## 文脈

Codex を取り込むと、`# AGENTS.md instructions` で始まるタイトルと「暗号化された内容は表示できない」という assistant の項目が大量に並ぶ。
基準コミット `408c7ef85584298d46a3c6a8592f996ed3a569d5` の `src/codex.ts` は、最初の user のテキストをタイトルに使い、暗号化部分を通常の text ブロックへ置き換える。
そのため、プロジェクト指示がタイトルになり、thinking の表示を切っても暗号化の代替テキストが残る。

2026-11-11 の調査時点では、ローカルの92ファイル中79ファイルの先頭 user がこの指示で始まり、78ファイルの `session_meta.payload.source` に `subagent` があった。
同じ調査で `reasoning` は4,788項目あり、すべてに `encrypted_content` があった。
件数は追記中のログの観察値であり、固定の仕様ではない。
続く調査では `source.subagent.thread_spawn` と `source.subagent.other = "guardian"` を確認した。
後者も通常の作業サブエージェントとしてまとめると、内部処理と利用者の会話を区別できない。

[ADR 0034](0034-import-codex-rollouts.md) の原本保持、変換結果の不変性、会話 ID、uuid、版の保持は維持する。
本 ADR は、タイトルの選択と GUI の既定表示を変更する。
暗号化された内容の復号や推測は行わない。

## 実装すること

### 1. 会話の分類

会話の分類は、そのファイルの先頭の `session_meta.payload.source` だけから決める。
後続に含まれる親のメタデータやタイトルの文言では分類しない。

| source の形 | 分類 | 保持する補足 |
| --- | --- | --- |
| 文字列 `vscode`、`exec`、`cli` | 通常 | source の値 |
| `subagent.thread_spawn` がオブジェクト | サブエージェント | 文字列の `parent_thread_id`、`agent_path`、`agent_nickname`、`agent_role` |
| `subagent.other` が文字列 | 内部処理 | その値。`guardian` 以外も同じ分類 |
| 欠落、未知の文字列、上記以外、複数の分類に一致 | 不明 | 元の source は原本で保持 |

`cli` は本調査で未観測だが、通常に分類する入力として明示的に定義する。
親 ID は表示と移動に使い、親子の会話や継承された履歴を統合しない。
親の会話が保存されていない場合は ID の表示だけにする。

GUI に会話種別の選択「通常」「サブエージェント」「内部処理」「すべて」を追加する。
起動時の既定は「通常」で、通常と不明の Codex 会話、および他提供元の全会話を含める。
「サブエージェント」と「内部処理」は、それぞれ該当する Codex 会話だけを含める。
「すべて」は全提供元の全会話を含める。
選択は同一起動中の画面切り替えでは維持し、次回起動時は通常へ戻す。

会話種別の条件を、プロジェクトの選択肢と件数、会話一覧、検索の結果と件数に同じように適用し、LIMIT と OFFSET より前に絞り込む。
既存の提供元と作業ディレクトリの条件とは AND で組み合わせる。
種別変更で現在のプロジェクト選択肢が消えた場合は「すべてのプロジェクト」に戻す。
開いている会話は維持し、親への移動や ID を指定した取得では分類による拒否をしない。
サブエージェントと内部処理の会話ヘッダーには分類と補足を表示する。

### 2. 表示タイトル

表示タイトルは、原本の物理行順に見た user の `response_item/message` の公開テキストから選ぶ。
暗号化ブロック、ツール結果、developer、system、エージェント間通信は候補にしない。
構造の判定には、input_text と output_text を元のブロック順に改行でつなぎ、CRLF を LF にそろえた文字列を使う。
見出しとタグが別の公開テキストブロックに分かれていても、同じ先頭構造として判定する。

プロジェクト指示と環境情報は、次の完全な先頭構造に一致した部分だけを候補から取り除く。
前後の空白を除き、次の構造を先頭から繰り返し消費する。

- `# AGENTS.md instructions` の見出し行に続く `<INSTRUCTIONS>…</INSTRUCTIONS>`。見出しの `#` と `AGENTS.md` の間の空白は0文字以上、見出しの他の文字は完全一致とする。
- `<environment_context>…</environment_context>`。

閉じタグが無い場合、先頭に通常の文がある場合、コードフェンスや引用の中に同じ語がある場合は削らない。
残りが空なら次の user を調べ、実際の依頼が同じメッセージの後ろにあれば、その残りを候補にする。
構造を除いた公開テキストの前後の空白を除き、改行を空白へ置き換えた先頭80 Unicode コードポイントを表示タイトルとする。
候補が無ければ会話 ID を表示する。
本文そのものから指示文を削除する変更ではない。

複数のスナップショットがある会話では、完成済み原本のバイト数が最も大きいものを選び、同じ長さなら SHA-256 の辞書順で最小のものから分類とタイトルを求める。
これを代表スナップショットと呼ぶ。
DB から再生成するときは、完成行までの長さを原本 source の `consumed_bytes`、ハッシュを保存パスのディレクトリ名から得る。
[ADR 0034](0034-import-codex-rollouts.md) の保存パスに一致しない原本は代表選択に使わず、対応する会話は有効な代表が無ければ不明として扱う。
規則を固定し、取り込み順でタイトルが変わることを防ぐ。
GUI の一覧、検索結果、ヘッダー、書き出しの既定ファイル名に表示タイトルを使う。
保存済みの custom-title と `session_summaries.title` は変更しない。

### 3. 暗号化項目の表示

原本の型を根拠に、変換時に作られた暗号化の代替ブロックの位置を記録する。
`reasoning.encrypted_content` と content 配列の `encrypted_content` を対象にする。
表示文字列だけを根拠に判定してはいけない。
利用者が「暗号化された内容は表示できない」と書いた通常の本文は隠さない。

GUI の「表示」に「表示できない内容」を追加し、既定をオフにする。
オンなら暗号化の代替ブロックを表示し、オフならそのブロックだけを隠す。
公開テキストや公開された思考の要約が同じ項目にあれば、それらは残し、既存の thinking の選択に従う。
表示するブロックが無くなった項目は見出しごと隠す。
この設定は既存のブロック表示設定と同じ方法で保存する。

GUI の検索では、暗号化の代替ブロックだけの一致を結果にしない。
「表示できない内容」の選択は本文表示だけに作用し、検索には作用しない。
既存の索引で候補を取り、原本から識別した代替ブロックを除いた本文で、GUI の既存の検索条件を再評価してから件数とページを確定する。
空白で分けたすべての検索語を満たすという規則を維持し、除外語などの新しい検索構文は追加しない。
一致する公開テキストを残すため、暗号化と公開内容が混在するレコードを一律に検索から除かない。

メッセージ番号、会話の総メッセージ件数、ページ取得の範囲は保存済みの全項目を基準とする。
暗号化だけの項目を隠しても番号を詰めず、GUI の会話欄には読み込み済み範囲で隠れた項目数を示す。
ページ全体が非表示でも前後へ読み進められるようにし、空の画面でページ読み込みを止めない。

### 4. データ構造と既存データへの適用

後続のスキーマ移行で、再作成できる表示用の表を追加する。
現在の版7の直後に実装する場合はスキーマ8とし、別の移行が先に採択された場合は実装前に番号の衝突を解消する。

| 表 | 主キー | 主な値 |
| --- | --- | --- |
| `codex_session_presentation` | `session_id` | 分類、表示タイトル、親 ID、補足、代表スナップショットのハッシュ、生成規則の版 |
| `codex_item_presentation` | `(session_id, uuid)` | 暗号化の代替ブロックの0始まりの位置の JSON 配列、生成規則の版 |

これらの表は Codex 専用である。
`records`、ペイロード、FTS、既存要約、公開済み `messages-v1.jsonl` と `manifest-v1.json` は書き換えない。
変換器 v1 の出力と uuid の計算規則も変更しない。
本変更によって同じ項目の新しい保存版を作らない。

表示用データは取り込み側で生成し、GUI は読み取り専用を維持する。
既存の `codex/rollout` の行をペイロード復元後に読み、先頭メタデータ、物理行番号、変換器 v1 の uuid を使って `codex/conversation` の項目へ対応付ける。
対応とブロック位置を検証できた項目だけに非表示の情報を付ける。
対応が不明な項目は隠さず、メタデータの無い会話は不明に分類して元のタイトルを使う。

スキーマ移行の SQL は表の追加だけを行う。
移行後の取り込みで過去の Codex 原本も走査し、会話単位のトランザクションで表示用データを生成する。
未生成または版が古い会話を再処理し、中断後も次回に再開できるようにする。
新しいスナップショットを取り込んだ場合は、その会話の代表選択と項目情報を再計算する。
処理失敗時はその会話の更新をロールバックして取り込みを失敗として報告し、他の会話は続ける。

新 GUI はこの移行後のスキーマ版を要求し、旧 DB には取り込みによる移行を案内する。
実装 PR で README と仕様書に、分類、タイトル、非表示の操作、件数と番号の意味、バックアップ後の移行手順を記載する。

## 実装しないこと

- 原本、暗号化データ、指示文、内部処理のログの削除。
- 暗号化内容の復号や、内容を推測したタイトル生成。
- 親子の自動統合、継承履歴の除去、元 ID と uuid の変更。
- CLI の一覧、検索、show、export の既定の絞り込み変更。CLI と Markdown の内容は従来どおり全記録を対象にし、GUI の書き出しも Markdown 本文は従来どおりとする。
- ChatGPT の取り込み、収集間隔の変更。

## 不変条件

1. **V1 保存の保持**: 移行と表示用データ生成の前後で、既存の原本、変換ファイル、records の rowid と復元 raw、uuid、FTS、既存要約は一致する。
2. **V2 分類の根拠**: 分類は代表スナップショットの先頭 source だけで決まり、タイトルや後続の親メタデータで変わらない。不明な会話は通常の一覧から消えない。
3. **V3 タイトルの選択**: 完全な既知の指示構造だけを候補から除き、残った最初の user の公開本文の先頭80コードポイント、または会話 ID を表示する。
4. **V4 非表示の限定**: 原本と対応付けた暗号化の代替ブロックだけを隠し、同じ文言の通常の本文と混在する公開内容は隠さない。
5. **V5 閲覧の一貫性**: プロジェクト、一覧、検索の件数とページは同じ会話種別条件を満たす。表示設定を変えてもメッセージ番号と保存上の総件数は変わらない。
6. **V6 再生成**: 同じ原本集合からは同じ表示用データが得られ、処理の中断や再実行で部分更新や新しいメッセージの版を作らない。

| 境界の入力 | 期待する結果 | 不変条件 |
| --- | --- | --- |
| 通常、thread_spawn、guardian、未知、source なし | 定義した分類。不明は通常に含む | V2 |
| 先頭が子、途中に親のメタデータ | 子の分類と親 ID を維持 | V2 |
| 指示だけ、指示の後に依頼、閉じタグなし、引用内の同じ語 | ID、依頼、元本文、元本文をタイトル候補にする | V3 |
| 見出しとタグが1ブロック、別々のブロック | どちらも完全な指示構造ならタイトル候補から除く | V3 |
| 本文が空、1文字、80文字、81文字、非 BMP 文字 | ID、1文字、80文字、先頭80文字、コードポイント単位 | V3 |
| 暗号化だけ、公開本文との混在、同文言の通常本文 | 既定で非表示、公開部分を表示、通常表示 | V4 |
| 全100項目が非表示、101件目に公開本文 | 番号を維持して次ページへ進める | V5 |
| 0件、1件、ページ上限、上限+1件の各分類 | 件数とページの条件が一致 | V5 |
| v1 のみの既存 DB、再実行、会話単位の中断、原本欠落 | 保存内容不変、決定的再生成、再開、未判定を隠さない | V1、V6 |

## テスト設計

V1 から V6 をテスト名に含め、実装前に失敗させる。
実物の本文をコミットせず、確認した構造を匿名化したフィクスチャで再現する。

- V1: 既存の各提供元と圧縮済み Codex 原本を含む DB の移行前後で、表の内容、原本ハッシュ、復元 raw、索引、要約を比較する。
- V2、V3: 分類とタイトルの純粋関数を境界表で検証する。複数スナップショットの取り込み順を逆にしても同じ結果になることを確認する。
- V4: 原本由来の代替ブロックの位置を検証する。公開 summary と暗号化が混在する reasoning、暗号化 agent_message、通常本文の同文言、対応不能の行を含める。
- V5: Rust の問い合わせで種別と既存フィルターの組み合わせ、検索条件の再評価、件数、ページ境界を確認する。GUI で既定値、切り替え、空ページからの継続、表示設定の保存を確認する。
- V6: 会話単位の更新途中で失敗させ、ロールバックと次回の再生成を確認する。新しい snapshot を加えても既存メッセージ数が表示用処理だけでは増えないことを確認する。
- 手動: 本番バックアップ上で既存データへの適用時間を測り、通常、サブエージェント、内部処理の切り替えと暗号化項目の再表示を確認してから本番へ適用する。

## トレードオフ

原本と変換結果を不変に保つため、表示用データを別に持ち、初回に過去の原本を読み直す必要がある。
通常の画面から内部処理を分ける一方、「すべて」と表示設定で保存内容を確認できるようにする。

タイトル判定は既知の構造に限定するため、将来の未知の指示形式はタイトルに残りうる。
表示不能な項目を隠すと番号に隙間ができるが、検索、CLI、書き出しで同じ番号を使えることを優先する。
GUI の表示タイトルと CLI の保存済みタイトルが異なることは、この表示専用の変更では許容する。
検索結果の再評価は、代替テキストの一致を多く含む検索では処理時間を増やすため、実装時に実物の DB で計測する。
