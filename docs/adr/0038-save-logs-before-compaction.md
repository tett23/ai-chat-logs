# ADR 0038: Codex と Claude Code のコンテキスト圧縮直前に会話ログを保存する

ステータス: 採択（未実装）

## 文脈

圧縮を迎えた会話を、次回の定期取り込みを待たずに chat-log で読み返したい。
保存対象は、フックがセッションの JSONL ファイルを読み取る時点で、ディスク上に末尾の改行まで書かれている行とする。

## 調査した事項

Codex の PreCompact フックには圧縮の契機を示す trigger があり、対象ファイルの transcript_path は省略される場合がある。
ai-chat-logs の src/codex-store.ts は最後の改行までを読み、内容の SHA-256 を名前にしたディレクトリへ原本と検索用のメッセージを保存する。
Claude Code の PreCompact は手動・自動いずれの圧縮でも transcript_path を渡す。成功時の標準出力は圧縮要約への指示として使われる。
既存の Claude Code 取り込みは元のパスを使い、改行までの行を SQLite に差分保存する。
bin/sync は全ソースを列挙し、一覧にないソースを欠落扱いにするために --mark-missing を指定する。

## 実装すること

手動圧縮と自動圧縮の両方で呼ぶコマンドを追加し、Codex と Claude Code のユーザー設定への登録例を README に載せる。
登録するコマンドの引数で提供元を指定し、標準入力のイベントから transcript_path を読む。成功時は標準出力を空にして終了コード 0 を返す。

Codex では AI_CHAT_LOGS_CODEX_DIR（既定は ~/.codex）の sessions または archived_sessions 以下にある通常の rollout ファイル一つを対象とする。
既存のスナップショット保存処理を使い、そのスナップショットの原本と検索用メッセージを既存のデータベースに取り込む。

Claude Code では CLAUDE_CONFIG_DIR（既定は ~/.claude）の projects 以下で既存の分類が claude-code/transcript となる通常ファイル一つを取り込む。
定期取り込みと同じパス、ソース種別、読み取り位置を使うため、どちらから先に取り込んでも続きから読める。

両方とも単一ファイルの取り込みでは --mark-missing を指定しない。

## 実装しないこと

圧縮後の要約を別形式で保存する機能は対象外とする。

## 不変条件

1. Claude Code では定期取り込みと同じ完成行を保存し、読み取り位置は最後の改行の直後と一致する。Codex では保存した原本は読み取り時点の最後の改行までのバイト列と一致する。
2. 同じ内容を再度取り込んでも、原本と検索結果の件数は増えない。
3. 対象外のセッションのソース状態は呼び出し前後で一致する。
4. パスがない場合、対象外のパスの場合、読み取りや保存に失敗した場合は標準エラーに理由を出して終了コード 1 を返す。標準出力は空とし、圧縮の停止を要求しない。

| 入力 | 期待する結果 |
| --- | --- |
| 空ファイル | 保存する行は 0 件、読み取り範囲は 0 バイト |
| 完結した行が一つ | その行の末尾の改行まで保存 |
| 完結した行の次に書きかけの行 | 最初の行の末尾の改行まで保存 |
| 同じファイルで連続して圧縮 | 追記がなければ件数は同じ |
| transcript_path がない | 診断を出して圧縮を続行 |

## テスト設計

不変条件の番号をテスト名に入れる。
両提供元の manual と auto について、一時ディレクトリと一時データベースで上表のイベントをコマンドの標準入力へ渡す。
Codex の原本はバイト単位、Claude Code の保存結果は行と読み取り位置で比較し、取り込んだ発言を chat-log で検索する（1、2）。
書きかけの行を完成させ、フックと定期取り込みを両方の順で実行して、その行を一度だけ検索できることを確認する（1、2）。
別セッションを先に登録し、対象だけの取り込み前後で別セッションの状態を比較する（3）。
対象外パスと書き込み不能な保存先も試し、診断が残ることとフックが圧縮を妨げないことを確かめる（4）。
各提供元の登録例は手動圧縮で動作を確かめる。

## トレードオフ

同期して取り込むため、圧縮開始までの待ち時間は対象ファイルの大きさに応じて延びる。
書きかけの行や一時的な失敗で取り込めなかったログは、既存の定期取り込みで回収する。
