# ADR 0042: chat-log のヘルプを全体とサブコマンドに分ける

Status: accepted

## 文脈

[ADR 0040](0040-session-and-message-ids-in-chat-log-and-gui.md) の受けいれ条件 A4 を、2026-11-17 に確かめた。
文脈を持たない2つのエージェント（Claude Code のサブエージェント）に、`chat-log --help` を使うことと、セッションIDかメッセージIDだけを渡した。
どちらのエージェントも会話を読めたので、A4 は満たされた。
しかし、どちらのエージェントも、`chat-log --help` の出力が長いためにツールの出力がファイルに逃がされ、冒頭だけを読んだと報告した。

冒頭だけで足りたのは、要る節（「利用者からIDを渡されたとき」）がたまたま冒頭にあったからである。
いまの全体のヘルプは、全サブコマンドのヘルプと共通のオプションを含む。
そのため、冒頭より後にしか書いていないこと（`show` の出力の形、`--around` の数え方など）は、エージェントに読まれないことがある。

利用者は、全体のヘルプとサブコマンドのヘルプに分けることを求めた。
この ADR は、全体のヘルプを、どのサブコマンドを使うかを決めるための短い案内にし、各オプションの詳しい説明をサブコマンドのヘルプに移すことを決める。

この ADR では、次の語を使う。

- **全体のヘルプ**：`chat-log --help`、`chat-log -h`、引数の無い `chat-log` の出力。いまは `src/chat-log/help.ts` の `MAIN_HELP` である。
- **サブコマンドのヘルプ**：`chat-log <サブコマンド> --help` の出力。
- **サブコマンドの節**：`help.ts` の `HELP` の値。いまは `CONTEXT`、`SESSIONS`、`SEARCH`、`SHOW`、`EXPORT` の5つの文字列である。後で `HELP` に足すもの（[ADR 0043](0043-chat-log-outline-of-long-sessions.md) の `outline` など）も含む。
- **共通のオプションの節**：`help.ts` の `COMMON` の文字列。
- **用語の節**：全体のヘルプの「用語:」から、「終了コード:」の前の空行までの文字列。
- **使い方の誤り**：`src/cli/chat-log.ts` の `usage()` を通って終了コード2になる誤り。区別できないセッションIDやデータベースが無いときの終了コード2は、`usage()` を通らないので含まない。

## 実装すること

### 1. 全体のヘルプ

全体のヘルプは、次の節をこの順に持つ。
「いまの節」は、この ADR を実装する時点の `MAIN_HELP` の節を指す。

1. 冒頭の説明（いまの節のまま）。
2. 利用者からIDを渡されたとき（いまの節のまま）。
3. 使う順序の勧め（いまの節のまま）。
4. サブコマンドの一覧：見出しの行 `サブコマンド:` の後に、サブコマンドの節ごとに `  <名前>  <何をするかの1文>` の行を、`HELP` のキーの順に置く。一覧の後に、空行を挟まずに `各サブコマンドのオプション、出力の形、既定値は chat-log <サブコマンド> --help で出す。` の行を置く。
5. 用語、終了コード、注意、例（いまの節のまま）。

一覧の1文は次のとおりとする。

| 名前 | 1文 |
| --- | --- |
| `context` | いまのプロジェクトの最近のセッションと、最後のやりとりを出す。 |
| `sessions` | セッションの一覧を新しい順に出す。 |
| `search` | 本文を全文検索し、ヒットを <ID>#<番号> で出す。 |
| `show` | 1つのセッションのメッセージを順に出す。メッセージIDで前後も出せる。 |
| `export` | 1つのセッションか1つのメッセージを Markdown の全文で出す。 |

[ADR 0043](0043-chat-log-outline-of-long-sessions.md) を先に実装したときは、その ADR が決めた `outline` の1文も、この表に加えて一覧に置く。

全体のヘルプは、サブコマンドの節と共通のオプションの節を含まない。

### 2. サブコマンドのヘルプ

サブコマンドのヘルプは、そのサブコマンドの節、空行、共通のオプションの節、空行、用語の節を、この順につないだものとする。
サブコマンドの節、共通のオプションの節、用語の節の中身は、いまのものから変えない。

共通のオプションの節は、どのサブコマンドのヘルプにもまるごと置く。
`--cwd`、`--since`、`--until` は、どのサブコマンドに効くかを共通のオプションの節が自分で書いている。
それ以外のオプションの既定値や、併用できないことは、各サブコマンドの節が書いている（`export` の節の「付けられない」など）。

`help.ts` は、`HELP` の値をサブコマンドの節だけのままにし、`COMMON` と用語の節の文字列（`TERMS` とする）を `export` する。
サブコマンドのヘルプは、`src/cli/chat-log.ts` が `HELP`、`COMMON`、`TERMS` からつなぐ。

### 3. 使い方の誤りの案内

使い方の誤りでは、argv の最初の要素が `HELP` のキーのとき、そのキーをサブコマンドとみなす。
オプションの解析に失敗したとき（知らないオプションなど）も、この規則でサブコマンドを決める。

サブコマンドを決められたときは、標準エラー出力の最後の行を `chat-log <サブコマンド> --help で使い方を出す。` にする。
argv が空のとき、または最初の要素が `HELP` のキーでないときは、いまの `chat-log --help で使い方を出す。` のままにする。

### 4. テスト

調査した事項の表の6つのテストは、確かめる中身を、その中身がある節を持つサブコマンドのヘルプから読むように直す。
確かめる文字列は変えない。

### 5. 文書

`docs/specifications.md` の `chat-log` のヘルプの項に、全体のヘルプとサブコマンドのヘルプの中身の分け方を書き、この ADR へのリンクを付ける。
`README.md` の「使い方は `chat-log --help` に全部書いてあり、AI はヘルプだけで使える。」を、「使い方は `chat-log --help` と `chat-log <サブコマンド> --help` に書いてあり、AI はヘルプだけで使える。」に直す。
`README.md` の「ヘルプ（`chat-log --help`）は…」の項に、サブコマンドの詳しい説明は `chat-log <サブコマンド> --help` で出すことを足す。

## 実装しないこと

- ヘルプの文面の書き直し。この ADR は、節の置き場所と、サブコマンドの一覧の行を変える。
- 共通のオプションの節を、サブコマンドごとに効くオプションだけに分けること。
- ヘルプの大きさの予算。逃がす境の大きさを確かめていないため、数値を決める根拠が無い。

## 不変条件

- I1：全体のヘルプは、`chat-log --help`、`chat-log -h`、引数の無い `chat-log` で同じ文字列であり、終了コードは0である。
- I2：全体のヘルプは、どのサブコマンドの節も、共通のオプションの節も、部分文字列として含まない。
- I3：全体のヘルプの `サブコマンド:` の行から、`各サブコマンドのオプション、出力の形、既定値は chat-log <サブコマンド> --help で出す。` の行までのあいだに、`HELP` のキーのそれぞれについて、`  <キー>  ` で始まる行がちょうど1つあり、ほかの行は無い。
- I4：`HELP` のどのキー `c` でも、`chat-log c --help` の標準出力は `HELP[c] + "\n\n" + COMMON + "\n\n" + TERMS + "\n"` と等しく、終了コードは0である。
- I5：全体のヘルプは、`利用者からIDを渡されたとき`、`使う順序の勧め`、`サブコマンド:`、`用語:`、`終了コード:`、`注意:`、`例:` を、この順に含む。
- I6：使い方の誤りでは、終了コードが2である。argv の最初の要素が `HELP` のキーなら、標準エラー出力の最後の行は `chat-log <そのキー> --help で使い方を出す。` であり、そうでなければ `chat-log --help で使い方を出す。` である。

| 入力 | 期待 | 不変条件 |
| --- | --- | --- |
| `chat-log`（引数なし） | 全体のヘルプ、終了コード0 | I1, I2, I3, I5 |
| `chat-log -h` | 全体のヘルプと同じ | I1 |
| `chat-log show --help` | `SHOW`、`COMMON`、`TERMS` | I4 |
| `chat-log sessions --help`（最も短い節） | `SESSIONS`、`COMMON`、`TERMS` | I4 |
| `chat-log show`（セッションIDなし、フィクスチャのデータベース） | 終了コード2、最後の行が `chat-log show --help で使い方を出す。` | I6 |
| `chat-log show --bogus` | 終了コード2、最後の行が `chat-log show --help で使い方を出す。` | I6 |
| `chat-log nosuch` | 終了コード2、最後の行が `chat-log --help で使い方を出す。` | I6 |
| `chat-log --bogus` | 終了コード2、最後の行が `chat-log --help で使い方を出す。` | I6 |

## 受けいれ条件

- A1：文脈を持たない AI のエージェント（Claude Code）に、`chat-log --help` を使うことと、メッセージIDだけを渡すと、追加の説明なしにその前後を読める。エージェントは、全体のヘルプを、ファイルに逃がされずに読む。

## テスト設計

`tests/chat-log.test.ts` に、次のテストを足す。
テストの名前は `ADR 0042 I<番号>: ...` とする。

1. `ADR 0042 I1, I5`：引数なし、`--help`、`-h` の出力が等しく、終了コードが0で、7つの見出しがこの順に現れる。
2. `ADR 0042 I2`：`HELP` のすべての値と `COMMON` のどれも、全体のヘルプに部分文字列として現れない。
3. `ADR 0042 I3`：一覧の範囲の行が、`HELP` のキーごとにちょうど1つずつある。
4. `ADR 0042 I4`：`HELP` のすべてのキーで、`--help` の出力が `HELP[c] + "\n\n" + COMMON + "\n\n" + TERMS + "\n"` と等しい。テストは `help.ts` から `HELP`、`COMMON`、`TERMS` を import する。
5. `ADR 0042 I6`：境界の表の4つの使い方の誤り。`chat-log show` はフィクスチャのデータベースで動かす。

調査した事項の表の6つのテストを、実装すること 4 のとおりに直す。

A1 は、実装の後に、文脈を持たないサブエージェントに、`chat-log --help` を使うことと、メッセージIDだけを渡して確かめる。
エージェントには、動かしたコマンドと、出力がファイルに逃がされたかを報告させる。

## トレードオフ

- エージェントは、サブコマンドのオプションを知るためにもう1回コマンドを動かす。代わりに、全体のヘルプは 3.5KB ほどになり（調査した事項の「残り」に、一覧の数行を足した大きさ。推測）、冒頭だけを読まれることがなくなると見込む。
- 共通のオプションの節と用語の節は、各サブコマンドのヘルプのそれぞれに入る。ソースではそれぞれ1つの文字列なので、食い違いは起きない。
- 共通のオプションの節には、そのサブコマンドでは付けられないオプションも並ぶ。付けられないことは各サブコマンドの節が書いているので、節を分けて食い違いの元を増やすより、まるごと置くほうを選ぶ。
