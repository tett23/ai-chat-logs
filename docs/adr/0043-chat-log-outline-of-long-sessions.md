# ADR 0043: chat-log で長いセッションの流れを短く出す

Status: accepted-pending

## 文脈

[ADR 0040](0040-session-and-message-ids-in-chat-log-and-gui.md) の受けいれ条件 A4 を、2026-11-17 に確かめた。
文脈を持たないエージェントに、セッションIDだけを渡して、会話を要約させた。
エージェントは要約を返したが、996 件のメッセージのセッションを、`chat-log show <セッションID> --offset <数>` で少しずつ読んだ。
Bash の呼び出しは 13 回で、そのうちの2回はシェルのループで `show` を何度も動かしていた（調査した事項）。
渡したセッションの流れを知るのに、これだけの手間がかかる。

利用者は、長いセッションを読む手間を減らすことを求め、ADR を作ることを頼んだ。
この ADR は、1つのセッションの中の、役割が `user` でテキストを持つメッセージ（下で「発言」と定義する）と、それぞれへの最後の応答だけを、1行ずつ出すサブコマンド `chat-log outline` を足すことを決める。

この ADR では、次の語を使う。

- **メッセージの番号**：セッションの中の通し番号（1始まり、時刻の順。写しは数えない。[ADR 0011](0011-cli-for-ai-agents.md)）。`show` の `## #<番号>` と同じ値である。
- **テキストのブロック**：`show --json` の `blocks` のうち、`kind` が `text` のもの。
- **発言**：役割が `user` で、`is_sidechain` が偽で、テキストのブロックを1つ以上持つメッセージ。利用者が打ったものかどうかは問わない。
- **区切り**：1つの発言から、次の発言の直前までのメッセージの並び。最初の発言より前にメッセージがあれば、それらは発言を持たない1つの区切りとする。
- **応答**：1つの区切りの中で、役割が `assistant` で、`is_sidechain` が偽で、テキストのブロックを1つ以上持つメッセージのうち、番号が最も大きいもの。
- **本文**：発言か応答のテキストのブロックの本文を `"\n"` でつなぎ、`src/chat-log/format.ts` の `flat`（`/\s*\n\s*/g` を空白1つにする）を当て、前後の空白を除いたもの。

## 調査した事項

手元のデータベース（2026-11-17）と、インストールした `chat-log`（main の e42e264）で、次を確かめた。

### A4 のエージェントが動かしたコマンド

A4 でセッションIDを渡したエージェントの記録（Claude Code のサブエージェントの JSONL）を、`jq` で数えた。

| 数えたもの | 数 |
| --- | --- |
| Bash の呼び出し | 13 |
| そのうち、`chat-log --help` | 1 |
| ループの中で `show` を動かした回数（`--offset 100` から `200` までと、`400` から `950` まで） | 3 と 12 |
| `chat-log show` を動かした回数の合計 | 23 |

### A4 で読んだセッションの中身

A4 で渡したセッション `70cfdb3d-01ad-4dd0-8592-53b31a63e09e`（Claude Code）を、`chat-log show 70cfdb3d-… --limit 2000 --json` で取り出し、`jq` で数えた。

| 数えたもの | 数 |
| --- | --- |
| メッセージ | 996 |
| 役割 `user`、ブロックは `tool_result` だけ | 323 |
| 役割 `assistant`、ブロックは `tool_use` だけ | 323 |
| 役割 `assistant`、ブロックは `thinking` だけ | 243 |
| 役割 `assistant`、ブロックは `text` だけ | 79 |
| 役割 `user`、ブロックは `text` だけ | 28 |
| 上の 28 件のうち、`is_sidechain` が偽のもの（発言） | 24 |
| 役割 `assistant`、`text` を持ち、`is_sidechain` が偽のもの | 76 |
| `chat-log show 70cfdb3d-… --limit 2000 \| wc -c`（既定の `--max-chars 2000`） | 224,583 バイト |

#1 は役割 `assistant` のテキストで、#2 が最初の発言である。

### 発言には、利用者が打ったものでないものが混ざる

上のセッションの発言の先頭と、`records.raw` の項目を、`sqlite3` と `jq` で確かめた。

| 番号 | 本文の先頭 | `raw` の項目 |
| --- | --- | --- |
| #2 | `<system-reminder> ## You are a session started from another session` | `origin` も `isMeta` も無い |
| #45 | `マージして実装` | `origin.kind` が `human` |
| #125 | `<task-notification> <task-id>…` | `origin.kind` が `task-notification` |
| #207 | `Base directory for this skill: …/skills/adr` | `isMeta` が真 |
| #371 | `<command-name>/goal</command-name>` | `origin` も `isMeta` も無い |
| #372 | `A session-scoped Stop hook is now active …` | `isMeta` が真 |

利用者が打った #371（`/goal`）は `origin` を持たず、利用者が打っていない #2 も `origin` を持たない。
そのため、`origin` と `isMeta` だけでは、利用者が打った発言を選び分けられない。

データベース全体では、`type` が `user` の記録を `json_extract(raw, '$.origin.kind')` と `json_extract(raw, '$.isMeta')` で数えた。
1,525,974 件がどちらも持たず、`origin.kind` が `human` のものは 4,192 件だった。
ほかに `task-notification`、`peer`、`coordinator` があった。
この数はツールの結果の記録も含む。

Codex のセッション `01a1d3b7-59fc-70d0-8aab-e6394db14706` では、役割 `user` でテキストを持つメッセージが 125 件あった。
そのうち 91 件は「The following is the Codex agent history added since your last approval assessment」で始まる、承認の判定のための入力だった。
`is_sidechain` が真のものは無かった。
Codex の `raw` に、利用者が打ったものかを示す項目があるかは確かめていない（未確認）。

### 大きなセッションを読む時間

メッセージの数がいちばん多いセッションを、`chat-log sessions --limit 100000 --json | jq -s 'sort_by(-.message_count)'` で探した。
`8bc4696d-626e-4e93-bc1b-d099b5427ae7`（Claude Code、133,373 件）で、次が `cb1691be-4aee-4682-b663-ec1ca710eb2d`（112,568 件）だった。

| コマンド | 出力 | 時間 |
| --- | --- | --- |
| `time chat-log export 8bc4696d-… \| wc -c` | 175,607,101 バイト | 29.7 秒 |
| `time chat-log export cb1691be-… \| wc -c` | 161,842,911 バイト | 49.5 秒 |

`cb1691be-…` を測ったときは、同じデータベースに対する別の重い問い合わせ（`records` の全件の `json_extract`）が同時に動いていた。
`8bc4696d-…` を測ったときに、同時に動くものがあったかは確かめていない（未確認）。

## 実装すること

### 1. `chat-log outline`

```
chat-log outline <セッションID> [--provider <名前>] [--limit <数>] [--offset <数>] [--max-chars <数>] [--json]
```

- セッションIDの解決（先頭8文字以上、区別できないときは終了コード2で候補、無いときは終了コード1）は、`show` と同じにする。
- 区切りを番号の順に並べ、`--offset` 個を読み飛ばし、`--limit` 個を出す。既定は `--limit 100`、`--offset 0` である。
- 区切りは、何も出さないもの（下）も含めて数える。
- 区切りごとに、発言があれば発言の行を、応答があれば応答の行を、この順に出す。発言も応答も無い区切りは、何も出さない。
- 本文は、`--max-chars`（既定 200、0 で切らない）で、`show` と同じ関数（`src/chat-log/blocks.ts` の `truncate`）で切る。切ったときは末尾に「…（N 文字のうち M 文字）」が付く。
- 思考、ツールの入出力、`is_sidechain` が真のメッセージは出さない。

テキストの出力は次の形とする。

```
# <提供元> <セッションID（全体）> <タイトル>（<メッセージの数> 件、発言 <発言の数> 件）
#<番号> user <時刻> <本文>
  #<番号> assistant <時刻> <本文>
（続き：chat-log outline <セッションID（全体）> --offset <数>）
```

- 1行目を「見出し」と呼ぶ。見出しは、どの `--offset` でも出す。
- 見出しのタイトルは、`show --message` の見出しと同じく、`flat` を当てたものとする。タイトルが無いときは空の文字列とする（`show --message` と同じ）。
- 見出しのメッセージの数は、`show` が数えるセッションのメッセージの数（`is_sidechain` が真のものも含む）である。発言の数は、セッションのすべての発言の数である。
- 「続き」の行は、出していない区切りが後に残るときだけ出す。`--offset` の値は、出した最後の区切りの次の区切りの位置である。
- `--provider` を付けたときは、「続き」の行の末尾に ` --provider <提供元>` を足す。`--limit` と `--max-chars` は「続き」の行に引き継がない。

`--json` では、発言と応答のそれぞれを1行の JSON にして、テキストの出力と同じ順に出す。
キーは `index`、`uuid`、`timestamp`、`role`、`text`、`truncated_from` とする。
`text` は、`show --json` と同じく、本文を `--max-chars` 文字で切っただけの文字列で、末尾の「…（N 文字のうち M 文字）」を付けない。
`truncated_from` は、切ったときは本文の元の文字数、切らなかったときは `null` である。
`--json` では、見出しと「続き」の行を出さない。

`--around`、`--message`、`--range`、`--thinking`、`--tools`、`--cwd`、`--since`、`--until`、`--all`、`--messages`、`--session`、`--exclude` は、`outline` と併用できない。
付けたときは使い方の誤り（終了コード2）として、標準出力には何も書かない。

### 2. ヘルプ

- `outline` のヘルプ（サブコマンドの節 `OUTLINE`）を足す。上の出力の形、既定値、`--limit` が区切りを数えること、併用できないオプションを書く。
- 全体のヘルプのサブコマンドの一覧に置く1文は、「1つのセッションの発言と、それぞれへの最後の応答を1行ずつ出す。長いセッションの流れを見る。」とする。
- 全体のヘルプの「利用者からIDを渡されたとき」のセッションIDの項の先頭に、`chat-log outline <セッションID>` で流れを短く見て、`chat-log show <セッションID> --around <番号>` で要るところを読む、という行を足す。
- 全体のヘルプの例に `chat-log outline 5a1e0a3b` を足す。

置き場所は、[ADR 0042](0042-split-chat-log-help-by-subcommand.md) を実装したかどうかで、次のとおりとする。

- [ADR 0042](0042-split-chat-log-help-by-subcommand.md) を実装した後なら、`OUTLINE` を `HELP` に足す。全体のヘルプには、一覧の1行だけを足す。
- [ADR 0042](0042-split-chat-log-help-by-subcommand.md) を実装する前なら、`OUTLINE` を `HELP` に足し、いまの `MAIN_HELP` の「サブコマンド:」の下の、`SHOW` と `EXPORT` のあいだにも置く。[ADR 0042](0042-split-chat-log-help-by-subcommand.md) を後で実装するときは、上の1文を一覧に置く。

### 3. 文書

`docs/specifications.md` の `chat-log` の節に `outline` を書き、この ADR へのリンクを付ける。
`README.md` の `chat-log` のサブコマンドの説明に `outline` を足す。

## 実装しないこと

- 利用者が打った発言だけを選び分けること。調査した事項のとおり、Claude Code の `origin` と `isMeta` では選び分けられず、Codex では確かめていない。`outline` は発言をすべて出し、本文の先頭（`<task-notification>` など）で読み手に見分けさせる。
- 応答を要約すること。`outline` は、記録にある本文を切って出すだけで、本文を作らない。
- `outline` での `--message`。メッセージIDから前後を読むには、いまの `show --message` を使う。
- GUI への同じ機能。
- 大きなセッションでの速さの予算。調査した事項の時間は、同時に動くものを確かめていない計測なので、数値を決める根拠にしない。

## 不変条件

- I1：テキストの出力の発言と応答の行の `#<番号>` のメッセージは、`chat-log show <セッションID> --around <番号> --limit 1 --json` の行と、`role` と `timestamp` が等しい。
- I2：`--offset 0` で区切りをすべて出したとき、発言の行の番号の並びは、セッションの発言の番号を昇順に並べたものと等しい。
- I3：各区切りについて、応答の行はちょうど応答の1行であり、応答が無い区切りには応答の行が無い。
- I4：`is_sidechain` が真のメッセージの番号は、どの行にも現れない。
- I5：発言と応答の行の本文は改行を含まず、`--max-chars` が正のときは、本文の「…（」より前の部分が `--max-chars` 文字以下である。
- I6：区切りの数を n とする。`--offset a --limit b` の出力の見出しより後の行は、区切りをすべて出した出力の、a 番目（0始まり）から b 個の区切りの行と等しい。「続き」の行は、a + b < n のときだけあり、その `--offset` の値は a + b である。
- I7：`--json` の各行の `index` と `role` は、同じ引数のテキストの出力の各行の番号と役割と、同じ順に一致する。`text` は、テキストの出力の本文から末尾の「…（N 文字のうち M 文字）」を除いたものと等しい。
- I8：実装すること 1 の併用できないオプションのどれかを付けると、終了コード2で、標準出力に何も書かない。
- I9：無いセッションIDでは終了コード1、区別できないセッションIDでは終了コード2で、`show` と同じ候補を標準エラー出力に書く。
- I10：`chat-log outline --help` は、`--limit` が区切りを数えることと、既定の `--limit 100` と `--max-chars 200` を含む。全体のヘルプの「利用者からIDを渡されたとき」の節は、`chat-log outline <セッションID>` を含む。

| 入力 | 期待 | 不変条件 |
| --- | --- | --- |
| 発言が1つで応答が無いセッション | 見出しと発言の行だけ | I2, I3 |
| 最初のメッセージが assistant のテキストのセッション | 先頭に応答の行だけの区切り | I3 |
| 最初の発言の前に、思考とツールの入出力だけがあるセッション | 何も出さない区切りを1つと数え、`--limit 1` では見出しと「続き」の行だけ | I6 |
| 1つの区切りに assistant のテキストが3つ | 番号が最も大きいものだけが応答の行 | I3 |
| サブエージェントの発言と応答を挟むセッション | どちらも出ない | I4 |
| 本文がちょうど `--max-chars` 文字 | 切らない | I5 |
| 本文が `--max-chars` + 1 文字 | 切って「…（」を付ける。`--json` の `truncated_from` は元の文字数 | I5, I7 |
| 改行と前後の空白を含む本文 | 1行で、前後の空白が無い | I5 |
| `--max-chars 0` | 切らない | I5 |
| 区切りの数とちょうど同じ `--limit` | 「続き」の行が無い | I6 |
| 区切りの数より1少ない `--limit` | 「続き」の行の `--offset` が `--limit` と等しい | I6 |
| `--offset` が区切りの数以上 | 見出しだけ | I6 |
| `--provider` を付けて「続き」の行が出る | 「続き」の行の末尾に `--provider <提供元>` | I6 |
| `--thinking` を付ける | 終了コード2 | I8 |
| 無いセッションID | 終了コード1 | I9 |

## 受けいれ条件

- A1：文脈を持たない AI のエージェント（Claude Code）に、`chat-log --help` を使うことと、セッション `70cfdb3d-01ad-4dd0-8592-53b31a63e09e` のIDだけを渡して会話を要約させる。エージェントは `outline` を使い、`chat-log show` を動かす回数が、A4 のときの 23 回より少ない。

## テスト設計

`tests/chat-log-outline.test.ts` に、フィクスチャのデータベースで次のテストを書く。
テストの名前は `ADR 0043 I<番号>: ...` とする。

1. `ADR 0043 I1, I2, I3`：発言、思考、ツールの入出力、assistant のテキストが混ざったセッションで、発言の行の番号が発言の番号と一致し、各区切りの応答の行が最も番号の大きい assistant のテキストで、番号ごとに `show --around` の行と役割と時刻が一致する。
2. `ADR 0043 I3, I6`：最初のメッセージが assistant のテキストのセッション、最初の発言の前に思考とツールの入出力だけがあるセッション、応答の無い区切りを持つセッション。
3. `ADR 0043 I4`：`is_sidechain` が真の発言と応答を挟むセッション。
4. `ADR 0043 I5, I7`：本文が `--max-chars` ちょうど、1文字あふれる、改行と前後の空白を含む、`--max-chars 0`。
5. `ADR 0043 I6`：`--limit` と `--offset` の組み合わせを、区切りの数の前後で変え、すべての出力の部分と一致することと、「続き」の行の有無と値。`--provider` を付けたときの「続き」の行。
6. `ADR 0043 I7`：同じ引数の `--json` とテキストの出力を比べる。
7. `ADR 0043 I8`：併用できないオプションをそれぞれ付ける。
8. `ADR 0043 I9`：無いセッションIDと、区別できないセッションID。
9. `ADR 0043 I10`：`outline` のヘルプと全体のヘルプ。

A1 は、実装の後に、文脈を持たないサブエージェントで確かめる。
エージェントには、動かしたコマンドを順にすべて報告させ、記録の JSONL から `chat-log show` の回数を数える。

## トレードオフ

- 発言を選び分けないので、`<task-notification>` やスキルの本文のような、利用者が打っていない発言も1行ずつ出る。A4 で読んだセッションでは、発言は 24 件である。調査した Codex のセッションでは、発言 125 件のうち 91 件が承認の判定の入力で、`outline` の行の大半を占める。
- 応答は区切りの最後の1つだけなので、途中の報告は出ない。途中を読むには、`show --around <番号>` を使う。
- 区切りを作るには、セッションのすべてのメッセージを読む。いちばん大きなセッションでは、`export` と同じほどの時間（調査した事項では 29.7 秒）がかかると見込む（推測）。
