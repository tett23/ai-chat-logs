# ADR 0044: chat-log outline の出力を短くする

Status: accepted-pending

## 文脈

[ADR 0043](0043-chat-log-outline-of-long-sessions.md) の `chat-log outline` を実装し、受けいれ条件 A1 を 2026-11-18 に確かめた。
文脈を持たないエージェントは、`chat-log show` を1回も動かさずに、996 件のセッションを要約できた。
しかし、`outline` の出力（11.5KB）は、Claude Code の Bash ツールによってファイルに逃がされた。
エージェントは、逃がされたファイルを `tail` と `grep` で読みなおしてから要約した。

利用者は、`outline` を短くする ADR を作ることを頼んだ。
この ADR は、`outline` のテキストの出力に既定で 8,000 バイトの上限を設け、本文の既定の長さを短くすることを決める。
上限を超えるのは、`--offset` の位置の区切り1つだけで上限を超えるときに限る。

この ADR では、[ADR 0043](0043-chat-log-outline-of-long-sessions.md) の語（発言、区切り、応答、本文、見出し）をそのまま使う。
加えて、次の語を使う。

- **逃がす境**：Claude Code の Bash ツールが、出力をそのまま返さずにファイルに保存し、先頭 2KB だけを返すようになる出力の大きさ。
- **発言の行**：発言を本文にした1行（`#<番号> user <時刻> <本文>`）。
- **応答の行**：応答を本文にした1行（`  #<番号> assistant <時刻> <本文>`）。
- **区切りの行**：ある区切りについて出す、発言の行と応答の行。何も出さない区切りでは0行である。
- **出力の大きさ**：テキストの出力の文字列（各行の末尾の改行を含む）の UTF-8 のバイト数。

## 調査した事項

### 逃がす境

文脈を持たないエージェント（Claude Code のサブエージェント、Sonnet）に、大きさを変えた出力を1回ずつ別の Bash の呼び出しで出させた。
エージェントの記録の JSONL を `jq` で読み、ツールの結果に「Output too large」があるかを確かめた。

| コマンド | バイト数 | 文字数 | 結果 |
| --- | --- | --- | --- |
| `head -c 10000 /dev/zero \| tr '\0' a` | 10,000 | 10,000 | そのまま返った |
| `head -c 10100 /dev/zero \| tr '\0' a` | 10,100 | 10,100 | 逃がされた |
| `yes あ \| tr -d '\n' \| head -c 9900` | 9,900 | 3,300 | そのまま返った |
| `yes あ \| tr -d '\n' \| head -c 10002` | 10,002 | 3,334 | 逃がされた |

逃がす境は、文字数ではなくバイト数で決まり、10,000 バイトから 10,100 バイトのあいだにある。
10,001 バイトから 10,099 バイトは測っていない（未確認）。
この境は、2026-11-18 の Claude Code での観察で、設定や版で変わるかは確かめていない（未確認）。

### いまの `outline` の大きさ

インストールした `chat-log`（`bin/install` を main の fab984e で実行した後のもの）で、3つのセッションの `outline` を、`--max-chars` を変えて測った。

| セッション | メッセージ | 発言 | `--max-chars` | バイト数 | 行数 |
| --- | --- | --- | --- | --- | --- |
| `70cfdb3d-…`（Claude Code、A1 で使ったもの） | 996 | 24 | 200（既定） | 11,793 | 45 |
| 同上 | | | 120 | 8,753 | 45 |
| 同上 | | | 80 | 7,216 | 45 |
| 同上 | | | 60 | 6,403 | 45 |
| `01a1d3b7-…`（Codex） | 343 | 125 | 200 | 57,762 | 201 |
| 同上 | | | 80 | 31,971 | 201 |
| `cb1691be-…`（Claude Code） | 112,568 | 1,244 | 200 | 58,723 | 185 |
| 同上 | | | 80 | 34,083 | 185 |

- `01a1d3b7-…` と `cb1691be-…` は、既定の `--limit 100` で区切りが残るので、末尾に「続き」の行がある。
- `70cfdb3d-…` の区切りの数は 25 である（`--offset 24` で1区切り、`--offset 25` で見出しだけが出る）。
- `70cfdb3d-…` の本文を `--json` で数えた。既定の `--max-chars 200` では、44 件の本文の文字数の中央値が 200（切られた）だった。`--max-chars 0` では、発言 24 件の本文が合わせて 37,861 文字、応答 20 件の本文が合わせて 6,614 文字だった。
- `70cfdb3d-…` の `--max-chars 80` の出力から時刻を除くと 6,116 バイトで、時刻は 1,100 バイトほどを占めていた。

本文を短くしても、区切りの数が多いセッションは境に収まらない。
`01a1d3b7-…` と `cb1691be-…` は、`--max-chars 80` でも 30KB を超えた。

## 実装すること

### 1. 本文の既定の長さ

`outline` の `--max-chars` の既定を、200 から 80 にする。

### 2. 出力の大きさの上限

`outline` に `--max-bytes <数>` を足す。
値は0以上の整数で、それ以外は使い方の誤り（終了コード2）とする。
既定は 8000 で、0 は上限を設けないことを表す。
`--max-bytes` は、`outline` のテキストの出力だけに効く。
`outline` 以外のサブコマンドに `--max-bytes` を付けたとき、および `outline` で `--json` と `--max-bytes` を一緒に付けたとき（値によらない）は、使い方の誤り（終了コード2）とする。

テキストの出力に出す区切りは、次のとおり決める。
区切りの数を n、`--offset` を o、`--limit` を L、`--max-bytes` を B とする。

- o ≥ n なら、見出しだけを出す。
- そうでなければ、区切り o から o+k−1 までの k 個を出す。k は、1 ≤ k ≤ min(L, n−o) を満たし、下の出力の大きさが B 以下になる最大の k とする。B が 0 なら、k = min(L, n−o) とする。そのような k が無いとき（区切り o だけで B を超えるとき）は、k = 1 とする。
- k 個を出したときの出力は、見出し、区切り o から o+k−1 までの区切りの行、そして o+k < n のときだけ「続き」の行（`--offset` が o+k）からなる。k を決めるときの出力の大きさも、この出力で数える。

「続き」の行の形は [ADR 0043](0043-chat-log-outline-of-long-sessions.md) のとおりで、`--provider` を付けたときだけ ` --provider <提供元>` を足す。
`--limit`、`--max-chars`、`--max-bytes` は、「続き」の行に引き継がない。

### 3. ヘルプ

`outline` のヘルプを次のとおり直す。

- コマンドの形の行に `[--max-bytes <数>]` を足す。
- 既定の行を `--limit 100、--max-chars 80、--max-bytes 8000` にする。
- `--max-bytes` の意味を書く。テキストの出力だけに効くこと、区切りの単位で止めること、`--offset` の位置の区切りは上限を超えても出すこと、0 で上限を設けないことである。
- 「続き」の行の説明に、`--limit` か `--max-bytes` で止めたときに出ることを書く。
- 併用できないオプションの行に、`--json` と `--max-bytes` の組を足す。

### 4. 文書

`docs/specifications.md` の `outline` の項の既定値と `--max-bytes` を直し、この ADR へのリンクを付ける。

### 5. 前の ADR のステータス

この ADR を採択するときに、[ADR 0043](0043-chat-log-outline-of-long-sessions.md) のステータスを次にする。

## 実装しないこと

- 時刻を短くすること。調査した事項のとおり 1,100 バイトほどを減らせるが、`show` と同じ形の時刻であることを優先する。
- 利用者が打っていない発言を省くこと。[ADR 0043](0043-chat-log-outline-of-long-sessions.md) の「実装しないこと」の理由のまま。
- 大きなセッションでの `outline` の速さ。
- `show` や `search` の出力の大きさの上限。

## 不変条件

- I1：`--json` を付けず、B が正で、o < n のとき、k ≥ 2 なら出力の大きさは B 以下である。k = 1 のときは、出力の大きさが B 以下であるか、区切り o+1 が無いか、区切り o と o+1 の2つを出すと B を超える。
- I2：`--max-bytes B` の出力の区切りの行は、同じ引数に `--max-bytes 0` を付けた出力の区切りの行の、先頭の k 区切りぶんと等しい。
- I3：「続き」の行は、o+k < n のときだけあり、その `--offset` は o+k である。どの B と L でも、`--offset 0` から、毎回同じ `--max-bytes B --limit L` を付けて「続き」の行の `--offset` をたどると、`--max-bytes 0 --limit n` の出力の区切りの行が、ちょうど1回ずつ同じ順に出る。
- I4：`--max-chars` を付けないときの本文は、80 文字を超える部分を切る。
- I5：`outline` で `--json` と `--max-bytes`（0 を含む）を一緒に付けたとき、`outline` 以外に `--max-bytes` を付けたとき、`--max-bytes` が0以上の整数でないときは、終了コード2で、標準出力に何も書かない。
- I6：`--json` の各行の `index` と `role` は、同じ引数に `--max-bytes 0` を付けたテキストの出力の各行の番号と役割と、同じ順に一致する。`text` は、テキストの出力の本文から末尾の「…（N 文字のうち M 文字）」を除いたものと等しい。
- I7：`chat-log outline --help` は、`--limit 100`、`--max-chars 80`、`--max-bytes 8000` と、`--limit` が区切りを数えることを含む。全体のヘルプの「利用者からIDを渡されたとき」の節は、`chat-log outline <セッションID>` を含む。

| 入力 | 期待 | 不変条件 |
| --- | --- | --- |
| 見出しとすべての区切りの行の大きさの合計が、ちょうど B | すべてを出し、「続き」の行が無い | I1, I3 |
| 上の合計が B+1 | 最後の区切りを出さず、「続き」の行を出す（その大きさが B 以下になるまで区切りを減らす） | I1, I2, I3 |
| 区切り o だけで B を超える | 見出し、区切り o の行、あれば「続き」の行 | I1, I3 |
| 見出しより小さい B（例：10） | 見出し、区切り o の行、あれば「続き」の行 | I1, I3 |
| 区切り o が何も出さない区切りで、区切り o+1 を足すと B を超える | 見出しと「続き」の行（`--offset` が o+1） | I1, I3 |
| `--max-bytes 0` | `--limit` だけで止める | I2, I3 |
| `--limit 1` と大きな B | 1区切りと、残れば「続き」の行（`--offset` が o+1） | I3 |
| o ≥ n | 見出しだけ | I3 |
| `--provider` を付けて「続き」の行が出る | 「続き」の行の末尾に `--provider <提供元>` | I3 |
| 本文がちょうど 80 文字と 81 文字 | 前者は切らず、後者は切る | I4 |
| `--json --max-bytes 100`、`--json --max-bytes 0` | 終了コード2 | I5 |
| `show <ID> --max-bytes 100` | 終了コード2 | I5 |
| `--max-bytes -1`、`--max-bytes abc` | 終了コード2 | I5 |
| テキストが 8,000 バイトを超えるセッションの `--json` | 行の数は `--max-bytes 0` のテキストの出力と同じで、既定のテキストの出力より多い | I6 |

## 受けいれ条件

- A1：インストールした `chat-log` で、`chat-log outline 70cfdb3d-01ad-4dd0-8592-53b31a63e09e` の出力が 8,000 バイト以下である。
- A2：文脈を持たない AI のエージェント（Claude Code）に、`chat-log --help` を使うことと、セッション `70cfdb3d-01ad-4dd0-8592-53b31a63e09e` のIDだけを渡して会話を要約させると、`outline` の出力がファイルに逃がされずに返る。

## テスト設計

`tests/chat-log-outline.test.ts` に、次のテストを足す。
テストの名前は `ADR 0044 I<番号>: ...` とする。
区切りの多いフィクスチャとして、本文が 80 文字の発言と応答の区切りを 120 個持ち、テキストの出力が既定で 8,000 バイトを超えるセッションを足す。

1. `ADR 0044 I1, I2, I3`：区切りの多いセッションで、B を、見出しとすべての区切りの行の合計ちょうど、その合計+1、区切り o より小さい値、10、0 に変え、L を 1、5、100 に変える。それぞれで、出力の大きさ、`--max-bytes 0` の出力との一致、「続き」の行の値を確かめ、同じ B と L を付けて「続き」の行をたどったときの区切りの行の並びを確かめる。o ≥ n、`--provider` つき、何も出さない区切りが o の場合も確かめる。
2. `ADR 0044 I4`：本文がちょうど 80 文字と 81 文字の発言。
3. `ADR 0044 I5`：境界の表の、終了コード2になる入力。
4. `ADR 0044 I6`：区切りの多いセッションで、`--json` と `--max-bytes 0` のテキストの出力を比べ、`--json` の行の数が既定のテキストの出力の区切りの行の数より多い。
5. `ADR 0044 I7`：`outline` のヘルプと全体のヘルプ。

いまのテストは、次のとおり直す。

- `ADR 0043 I6` のテスト（`--offset` と `--limit` と「続き」の行）は、`--max-bytes 0` を付けて同じことを確かめるように直し、名前を `ADR 0044 I3` にする。
- `ADR 0043 I3, I6` のテスト（何も出さない最初の区切り）は、名前を `ADR 0043 I3, ADR 0044 I3` にする。中身は変えない（フィクスチャが小さく、既定の上限に達しない）。
- `ADR 0043 I7` のテストは、`--max-bytes 0` を付けたテキストの出力と比べるように直し、名前を `ADR 0044 I6` にする。
- `ADR 0043 I10` のテストは、既定値を 80 と 8000 に直し、名前を `ADR 0044 I7` にする。
- `ADR 0043 I5, I7` のテスト（本文の切り方）は、`--max-chars` を明示しているので、中身も名前も変えない。

A1 は、実装の後に `chat-log outline 70cfdb3d-… | wc -c` で確かめる。
A2 は、文脈を持たないサブエージェントで確かめ、記録の JSONL で、`outline` のツールの結果に「Output too large」が無いことを確かめる。

## トレードオフ

- 既定の 8,000 バイトは、調査した事項の逃がす境（10,000 バイトから 10,100 バイト）より小さくとった。エージェントがコマンドに行を足すこと（`; echo exit=$?` など）と、境が版で動くことへの余裕である。逃がす境は Claude Code の振る舞いなので、ほかのエージェントには当てはまらない。それでも、8,000 バイトはほかのエージェントにとっても一度に読みやすい大きさとみる（推測）。
- 区切りの数の多いセッションでは、1回の `outline` で全体が見えなくなる。「続き」の行をたどれば、全部を読める。
- 本文を 80 文字で切ると、発言の意図が先頭だけでは分からないことがある。そのときは `show --around <番号>` で読む。
- `--offset` の位置の区切りを上限を超えても出すのは、1つの区切りが上限より大きくても、「続き」の行をたどって先へ進めるためである。
